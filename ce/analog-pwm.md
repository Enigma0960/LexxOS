# Аналоговый вход и PWM

`AnalogInput` и `PwmOutput` — переносимые интерфейсы без типов ESP-IDF и FreeRTOS. Порт предоставляет фабрики в
`PlatformServices`, а `DeviceManager` создаёт объекты из описания платы при `bootstrap()`.

```cpp
constexpr lexxos::platform::AnalogInputConfig inputs[]{
    {.name = "knob", .pin = {34}, .resolutionBits = 12,
     .attenuation = lexxos::platform::AnalogAttenuation::Db12},
};
constexpr lexxos::platform::PwmOutputConfig outputs[]{
    {.name = "led", .pin = {2}, .channel = 0, .timer = 0,
     .frequencyHz = 1000, .resolutionBits = 10,
     .activeLevel = lexxos::platform::GpioActiveLevel::High,
     .initialDutyPermille = 0},
};
// В LegacyBoardDescriptor:
// .analogInputs = inputs,
// .pwmOutputs = outputs,

auto* knob = system.devices().analogInput("knob");
auto* led = system.devices().pwmOutput("led");
std::uint32_t raw{};
if (knob && led && knob->readRaw(raw)) {
    auto duty = static_cast<std::uint16_t>(
        static_cast<std::uint64_t>(raw) * 1000 / knob->maxCode());
    if (!led->setDutyPermille(duty)) {
        // Приложение обрабатывает ошибку записи.
    }
}
```

Списки и строки имён должны жить столько же, сколько описание платы. Полученные указатели действуют до
`DeviceManager::initialize()` или уничтожения ядра. Предусмотрено до восьми входов и восьми PWM-выходов. Пустые списки
не создают аппаратных ресурсов.

Перед созданием драйверов проверяются диапазоны, повторения имён и выводов внутри аналоговых/PWM-списков, уникальность
PWM-каналов и совместимость таймеров. Аналоговые и PWM-выводы не могут совпадать с `statusLed`, `debugUart`, `userGpio`,
линиями именованных I²C/SPI и их CS. При отказе фабрики или дальнейшей инициализации платы созданные объекты
освобождаются. Освобождение PWM в порте ESP32 переводит выход в неактивное состояние.

## AnalogInput

- `isReady()` — драйвер инициализирован.
- `readRaw(code)` — новое измерение в диапазоне `0…maxCode()`.
- `hasCalibration()` — доступен перевод результата в милливольты.
- `readMillivolts(mV)` — отдельное калиброванное измерение.

Оба чтения возвращают `false` при ошибке и сохраняют выходной аргумент. Без калибровки `readMillivolts()` также
возвращает `false`; сырой код остаётся доступен. Ноль является допустимым результатом. Вызовы выполняются
последовательно из контекста задачи, не из ISR.

В ESP32 используется ADC oneshot, разрядность 9–12 бит и ослабление `Db0`, `Db2_5`, `Db6`, `Db12`. Блок ADC совместно
используется его каналами и освобождается после последнего владельца. Калибровка берётся из eFuse через ESP-IDF line
fitting. Если eFuse не содержит подходящих данных, порт не подставляет предполагаемое опорное напряжение. Напряжение
питания 3,3 В не означает линейный измерительный диапазон до 3,3 В: границы и точность зависят от ослабления и
чипа. [Калибровка АЦП ESP32](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/adc_calibration.html).

Для совместной работы с Wi-Fi предпочтителен ADC1. ADC2 может быть занят радиоподсистемой; такой отказ передаётся
приложению как ошибка чтения. GPIO34–39 не имеют внутренних подтяжек; неподключённый вход не даёт осмысленного
измерения.

## PwmOutput

- `setDutyPermille(0…1000)` — заполнение с шагом задания 0,1%.
- `dutyPermille(value)` — последнее подтверждённое задание; это не измерение физического сигнала.
- `frequencyHz()` — фактическая частота аппаратного таймера.
- `isReady()` — драйвер инициализирован.

`0` задаёт постоянно неактивный выход, `1000` — постоянно активный. Полярность определяется `activeLevel`. Значения вне
диапазона отклоняются до обращения к оборудованию и сохраняют прошлое задание. После ошибки аппаратной записи состояние
считается неизвестным: `dutyPermille()` возвращает `false`, сохраняя аргумент. Успешная следующая запись восстанавливает
известное состояние.

Порт ESP32 использует LEDC low-speed: каналы 0–7, таймеры 0–3, разрешение 1–20 бит. Достижимость сочетания частоты и
разрядности проверяет ESP-IDF. Разрешение определяет реальный шаг заполнения; промежуточные значения округляются к
аппаратному коду. Крайние значения реализованы постоянным уровнем, без записи недопустимого кода
счётчика. [LEDC ESP32](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/ledc.html).

Каналы могут разделять таймер только при одинаковых `frequencyHz` и `resolutionBits`. Таймер освобождается после
последнего канала. Выбранные номера low-speed каналов и таймеров принадлежат CE; не перенастраивайте их напрямую через
ESP-IDF или другую библиотеку. Частота задаётся в конфигурации платы и не изменяется через объект отдельного выхода.
Методы одного объекта вызываются последовательно одним владельцем.

## Подключение SDK

В адаптере приложения добавьте зависимости ESP-IDF `esp_adc` и `esp_driver_ledc` рядом с зависимостями GPIO/I²C/SPI.
Используйте библиотеки и заголовки из одного SDK: описание платы и `PlatformServices` расширены. Готовый автономный
пример поставляется в `examples/analog_pwm`; в репозитории он находится в `examples`.

Проверка сборки не подтверждает точность АЦП, частоту или уровни PWM на конкретной плате. Аппаратная приёмка включает
измерение этих параметров и проверку крайних значений заполнения для обеих полярностей.

Аналоговые выходы ЦАП описываются через `analogOutputs` и участвуют в той же проверке
конфликтов. [Интерфейс AnalogOutput](analog-output.md).
