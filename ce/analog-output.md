# Аналоговый выход

`AnalogOutput` задаёт код ЦАП через переносимый интерфейс. Платформа создаёт драйвер,
а приложение получает готовый объект по имени из `DeviceManager`.

```cpp
constexpr lexxos::platform::AnalogOutputConfig outputs[]{
    {.name = "reference", .pin = {25}, .resolutionBits = 8, .initialCode = 0},
};
// В LegacyBoardDescriptor: .analogOutputs = outputs,

auto* output = system.devices().analogOutput("reference");
if (output && output->writeRaw(128)) {
    std::uint32_t code{};
    if (output->currentCode(code)) {
        // code — подтверждённое задание, а не измеренное напряжение.
    }
}
```

## Контракт

- `isReady()` — канал инициализирован.
- `maxCode()` — максимальный код ЦАП.
- `writeRaw(code)` — установить код в диапазоне `0…maxCode()`.
- `currentCode(code)` — получить последнее подтверждённое задание.

Значение вне диапазона возвращает `false` до обращения к оборудованию: выход и
сохранённый код не меняются. При аппаратной ошибке состояние считается неизвестным.
В этом случае `currentCode()` возвращает `false`, сохраняя выходной аргумент.
Следующая успешная запись снова делает состояние известным. Методы одного объекта
вызываются последовательно одним владельцем из задачи, не из ISR.

Интерфейс и конфигурация не зависят от ESP-IDF или FreeRTOS. Другая платформа
предоставляет фабрику `PlatformServices::createAnalogOutput`. Пустой список не
требует фабрики и не выделяет аппаратные ресурсы.

## Описание платы и время жизни

`AnalogOutputConfig` содержит имя, GPIO, разрядность и начальный код. В переносимом
реестре помещается до восьми аналоговых выходов; реальное число определяется портом.
Проверяются начальный код и разрядность 1–32 бита, дубли имён и выводов среди
AnalogInput, AnalogOutput и PWM. Выводы не могут совпадать с `statusLed`,
`debugUart`, `userGpio`, линиями именованных I²C/SPI и их CS.

Описание, таблицы и строки имён должны жить столько же, сколько плата. Драйверы
создаются при `bootstrap()` и принадлежат `DeviceManager`. Полученные указатели
недействительны после сброса реестра или уничтожения ядра. Ошибка фабрики откатывает
создание всей группы аналоговых/PWM-устройств; ошибка дальнейшей загрузки также
освобождает их. Откат освобождает ресурсы, но не восстанавливает прежний внешний
аналоговый сигнал.

## Порт ESP32

Используется `driver/dac_oneshot.h` из ESP-IDF 6.0.2. На классическом ESP32 доступны
GPIO25 и GPIO26 с разрешением 8 бит и диапазоном кода 0–255. Неподдерживаемые GPIO
или разрешение отклоняются при инициализации. ESP-IDF резервирует DAC-канал и не
позволяет одновременно занимать его драйверами oneshot, cosine или continuous.
Не перенастраивайте занятый вывод напрямую через GPIO, ADC или другую библиотеку.
[DAC в ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v6.0.2/esp32/api-reference/peripherals/dac.html).

Начальный код записывается при создании драйвера. При удалении объекта канал
отключается: удержание заданного напряжения или нулевой уровень после освобождения
не гарантируются. Приложение может явно вызвать `writeRaw(0)`, пока канал активен.

Перевод кода в точное напряжение требует знания опорного напряжения и характеристик
выхода. Этот API не обещает калиброванные милливольты. Измерение напряжения выполняется
внешним прибором или отдельным аналоговым входом. Формирование сигналов с точной
частотой через DMA не входит в контракт `AnalogOutput`.

## Подключение SDK

Адаптер автономного проекта добавляет `esp_driver_dac` в зависимости компонента и
предварительно собранной библиотеки порта. Используйте `.a` и заголовки из одного
SDK, поскольку `LegacyBoardDescriptor`, `PlatformServices` и `DeviceManager` расширены.

Пример `analog_output` хранит описание платы, настройки ESP-IDF и прикладной цикл
в своей папке. В дистрибутиве это `examples/analog_output`, в репозитории —
`examples`. Он собирается без доступа к исходникам ядра.

Аппаратная приёмка остаётся отдельным этапом: измерение уровней, проверка обоих
каналов и поведения при остановке или повторной инициализации.
