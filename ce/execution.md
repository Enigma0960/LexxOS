# Исполнение LexxCE

Базовый режим CE — короткие обработчики в общем кооперативном цикле. Приложение вызывает `CooperativeLoop::poll(nowMs)`
и возвращается к своему циклу. Обработчики выполняются последовательно в вызывающем контексте. Каждый обработчик должен
быстро возвращать управление.

## Состав библиотеки

| Архив                        | Назначение                                                                                 |
|------------------------------|--------------------------------------------------------------------------------------------|
| `liblexxos_ce.a`             | Переносимое ядро, реестр, драйверные интерфейсы, события и `CooperativeLoop`.              |
| `liblexxos_ce_cooperative.a` | Кооперативная реализация ожиданий и совместимость с общими функциями ядра.                 |
| `liblexxos_ce_freertos.a`    | Подключаемая реализация задач с отдельными стеками и блокирующей синхронизации на ESP-IDF. |
| `liblexxos_ce_espidf.a`      | Платформенные службы ESP32, GPIO, I²C и SPI через ESP-IDF.                                 |

Приложение подключает ядро, порт своей платформы и ровно один компонент исполнения — `cooperative` или `freertos`. Все
архивы и заголовки берутся из одного SDK. Для старых автономных проектов нужно обновить
`components/lexxos_ce/CMakeLists.txt` по одному из новых примеров.

Порт ESP-IDF использует FreeRTOS внутри платформенных драйверов и при ожидании процессора. ESP-IDF запускает системный
планировщик до `app_main`, поэтому он присутствует в ESP32-прошивке и при кооперативном приложении. Полностью свободная
от FreeRTOS прошивка требует платформенного порта с другим загрузочным трактом и
HAL. [Порядок запуска ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-guides/startup.html).

## Выбор в автономном примере

По умолчанию выбирается `cooperative`. В ESP-IDF-проекте выбор задаётся при конфигурации приложения.

```sh
idf.py -DLEXXOS_CE_SDK=/path/to/sdk -DLEXXOS_CE_EXECUTION=cooperative build
idf.py -DLEXXOS_CE_SDK=/path/to/sdk -DLEXXOS_CE_EXECUTION=freertos build
```

В `blink` кооперативный режим вызывает шаг переключения LED раз в секунду. В режиме `freertos` используется отдельная
задача. Остальные примеры выполняют собственную последовательность действий в `app_main`.

## Кооперативные обработчики

```cpp
#include <lexxos/kernel/cooperative/cooperative_loop.h>

lexxos::kernel::CooperativeLoop loop;
bool registered = loop.add(
    [](void* context) {
        auto& app = *static_cast<Application*>(context);
        return app.tick(); // false завершает этот обработчик.
    },
    &application, 1000, clock.uptimeMs());

if (registered) {
    while (loop.taskCount()) {
        loop.poll(clock.uptimeMs());
        clock.sleepMs(1);
    }
}
```

Цикл содержит до восьми обработчиков. Первый вызов происходит после заданного периода. Период 0 означает один вызов на
каждый `poll`. Пропущенные периоды объединяются в один вызов. Максимальный период — `INT32_MAX` мс. Передавайте
монотонный 32-битный счётчик миллисекунд и вызывайте `poll` чаще одного раза за `INT32_MAX` мс, чтобы сравнение сроков
корректно работало через переполнение счётчика.

Регистрация, опрос и чтение состояния цикла выполняются из одной задачи. Регистрация из обработчика и повторный
вложенный `poll` отклоняются. Обработчик возвращает `false`, чтобы освободить свой слот.

`kernel::createTask` в кооперативном компоненте возвращает `false`. Собственные стеки предоставляет выбранный задачный
планировщик. `kernel::taskCount` относится к таким задачам, а `CooperativeLoop::taskCount` — к обработчикам конкретного
цикла. `sleepMs` внутри обработчика приостанавливает весь вызывающий цикл, поэтому интервалы задавайте аргументом
`periodMs`.

В кооперативном компоненте `Event::wait`, `Mutex::lock` и `Semaphore::acquire` возвращают результат сразу при любом
timeout. При занятом ресурсе обработчик должен вернуть управление и повторить попытку позже. В компоненте FreeRTOS те же
операции поддерживают блокирующее ожидание. В CE метод `EventBus::publishFromIsr` возвращает `false`, если буфер событий
в этот момент занят. ISR должен учитывать этот результат.

## Сборка без FreeRTOS и ESP-IDF

Из корня репозитория можно собрать переносимое ядро и кооперативный компонент обычным C++20-компилятором.

```sh
cmake -S ce -B build/ce-cooperative
cmake --build build/ce-cooperative
```

Готовые архивы и публичные заголовки экспортируются в `build/ce-cooperative/sdk`. Они собраны для выбранного компилятора
и его целевой архитектуры. По умолчанию это архитектура компьютера сборки. Для контроллера передайте CMake toolchain
своей платформы.

Приложение передаёт `PlatformServices` в `CoreSystem`, включая описание платы, GPIO, часы и консоль. Платформенные
службы реализует приложение или отдельный HAL-порт. При компиляции всех потребителей задайте `LEXXOS_EDITION_CE=1` и
используйте экспортированный `include/`. При статической линковке ядра и компонента исполнения разрешите циклические
ссылки архивов, например через `--start-group/--end-group` в GNU ld.

Переносимая сборка позволяет компилировать и линковать ядро без RTOS. Готовый bare-metal порт ESP32 в этот комплект не
входит.
