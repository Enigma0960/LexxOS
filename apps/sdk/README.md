# Гостевой SDK LexxOS (RV32I)

## Актуальное состояние UI и подготовка графической игры (S5.14)

- Системный `TreeWindowV3` поддерживает атомарные пакеты `beginBatch()`,
  `commitBatch()`, `rollbackBatch()`; `Tabs::select()` использует один пакет
  для удаления предыдущей страницы, вставки новой и выделения вкладки.
- `UiCapabilities.flags` содержит `capability_atomic_patch_flags` (0x04).
  В версии протокола v3 операция 15 допускает обновление флагов (kind=4)
  без изменения структуры wire ABI.
- `ScrollList`, `Dropdown` и списки вкладок используют независимые
  ограниченные хранилища, количество которых определяется профилем платы.
- `graphics.h` — отдельный слой для спрайтов и игрового рендеринга,
  `ui.h` — системный интерфейс для меню и настроек.

Актуальные сведения приведены в [описании LexxUI S5.14](../../docs/lexxui-s514-atomic-tabs.md).

`lexx/lexx.h` определяет гостевой ABI и обёртки системных вызовов.
`lexx/runtime.cpp` содержит общие вспомогательные функции для автономной
среды RV32I: умножение, знаковое и беззнаковое деление/остаток,
`memcpy`, `memset`, `memmove`.

Каждый `.lexx` — независимый статически скомпонованный образ. Общими являются
исходники и этап сборки среды выполнения; динамической системной библиотеки
или сервиса прошивки здесь нет. Загрузчик и ABI `.lexx` сохраняют совместимость.

## Сборка приложений

`apps/CMakeLists.txt` компилирует среду SDK один раз для каталога сборки
и добавляет объектный файл при компоновке каждого приложения. В `SOURCES`
перечисляйте только исходники приложения; вручную добавлять `runtime.cpp` не нужно.

```sh
cmake --preset apps
cmake --build --preset apps
```

В отдельном Makefile компонуйте исходник среды SDK вместе с приложением,
как в `apps/examples/lexx/{hello,cat}/Makefile`. Для обоих используйте одинаковые
`-march=rv32i -mabi=ilp32`, `-ffreestanding -fno-builtin` и остальные флаги ABI.

Эта среда принадлежит гостевой VM и не должна компоноваться с прошивкой
самой ОС. Приложению нужны символ `_start` и стандартный скрипт компоновщика
`apps/sdk/lexx/lexx.ld` из гостевого SDK.

## Доступ к устройствам

Подключите `<lexx/devices.h>` для работы с зарегистрированными GPIO, I2C,
SPI и UART. При упаковке программа должна объявить возможность `devices`.
Все обращения проходят через системные вызовы ОС; гостю не передаются
указатели на устройства ОС или адреса аппаратных регистров.

Устройство открывается по зарегистрированному имени. Успех возвращает
целочисленный дескриптор, отрицательное значение — ошибку:

- `-1` — неверный аргумент или дескриптор;
- `-2` — устройство не найдено;
- `-3` — устройство занято;
- `-4` — доступ запрещён;
- `-5` — устройство не готово;
- `-6` — операция не поддерживается;
- `-7` — ошибка ввода-вывода;
- `-8` — таблица дескрипторов заполнена.

`device_info()` перечисляет устройства, `device_open()` и `device_close()`
получают и освобождают их. Дескриптор принадлежит экземпляру гостевой VM;
при завершении VM оставшиеся дескрипторы освобождаются автоматически.

Обычно владение исключительное. I2C и SPI допускают открытие несколькими
приложениями. Короткие I2C-транзакции выполняются последовательно через
приоритетную очередь контроллера: внутренние драйверы используют `System`,
гостевые запросы — `Normal` с ожиданием до 50 мс. При равном приоритете
действует FIFO; начатая передача не вытесняется. Системные I2C-адреса
зарезервированы и недоступны гостю, в том числе через псевдонимы той же
физической шины. Истечение ожидания возвращает `Busy`.

SPI последовательно выполняет всю синхронную операцию: настройку частоты
и режима, установку CS, передачу и снятие CS. Гостевой запрос с приоритетом
`Normal` ждёт до 50 итераций по 1 мс, затем возвращает `Busy`. Приоритет
влияет только на ожидающие запросы. Имя SPI обозначает конечное устройство
с заданным CS; гость не выбирает произвольный вывод CS. Устройства одного
контроллера должны использовать общую `BusTransactionQueue`; псевдонимы
одного объекта разделяют её автоматически. Ненулевая частота задаёт нужную
скорость, ноль сохраняет текущую. Очередь не предоставляет исключительного
владения протоколом на несколько отдельных операций.

GPIO ограничены пользовательскими выводами, зарегистрированными платой.
SPI и UART явно регистрируются поставщиками устройств или платы.
Системную шину нельзя публиковать без политики владения ресурсами.
Передачи синхронные, до 256 байт за операцию; UART-чтение не должно ждать бесконечно.
