# Операции с файлами Lexx Commander

Для этой сборки необходимы обновлённые ядро LexxOS и SDK: приложение
запрашивает `storage-read` и `storage-write`, использует ABI syscall 13–18.
Старые `.lexx` остаются совместимыми.

| Клавиша        | Действие                                           |
|----------------|----------------------------------------------------|
| `F5`, `C`      | Скопировать выбранный файл/каталог в другую панель |
| `F6`, `M`      | Переместить выбранный файл/каталог в другую панель |
| `N`            | Переименовать выбранный объект (ввести новое имя)  |
| `F8`, `Delete` | Удалить файл или каталог с подтверждением `Y`      |

Папки копируются рекурсивно, включая скрытые элементы независимо от настройки
отображения. Максимальная вложенность обхода — 8 уровней, максимум 8192
записей на каталог. Операция останавливается с сообщением, если достигнут лимит
или обнаружена ошибка. `F6` пытается вызвать VFS `rename` и только при ошибке
`CrossFilesystem` / `CrossDirectory` выполняет копирование, затем удаление
оригинала. Перезапись существующих объектов запрещена.

Ограничения и безопасность:

* Удаление дерева рекурсивное, необратимое, подтверждается только клавишей Y.
* Источник при ошибке копирования сохраняется; возможен **неполный** каталог
  назначения, который нужно проверить и удалить вручную.
* При ошибке удаления уже скопированного дерева перенос может оставить обе копии.
* `open_write_new` проверяет отсутствие назначения, но существующий VFS API
  `CreateTruncateWrite` пока не предоставляет атомарное `O_EXCL`. В конкурентном
  сценарии между проверкой и открытием возможна гонка — до полноценной
  реализации exclusive-create не используйте его для защищённых данных.
* Каталоги `/`, `/proc`, `/sys`, `/dev`, `/mnt`, `/tmp` защищены от удаления;
  системные псевдофайлы не удаляются через VFS.
* Время и `/proc/*` по-прежнему показывают динамическое содержимое без снимка.
* Имя переименовываемого объекта вводится в ASCII; символы `/` и `\\` запрещены.
