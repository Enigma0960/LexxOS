# LexxUI S5.4 — системные уведомления и размещение элементов

**LexxOS рисует интерфейс и обрабатывает ввод, SDK передаёт описания и
получает события**. Предыдущий ABI `Document`, `Control`, `Event` и `ListItems` не изменён.

## Уведомления

`#include <lexx/ui/message_box.h>` предоставляет `MessageBox`:

```cpp
using namespace lexx::ui;
auto result = MessageBox::question("Confirm", "Apply new settings?").exec();
if (result == DialogResult::Ok) {
    // commit
}
```

| Вид            | Фабрика                   | Цвет заголовка | Кнопки      |
|----------------|---------------------------|----------------|-------------|
| Информация     | `MessageBox::information` | Синий          | OK          |
| Предупреждение | `MessageBox::warning`     | Оранжевый      | OK          |
| Ошибка         | `MessageBox::error`       | Красный        | OK          |
| Вопрос         | `MessageBox::question`    | Зелёный        | OK / Cancel |

`DialogResult::Ok=1`, `Cancel=2`, `Failed=-1`. У вопроса начальным выбором является **Cancel**. `Escape` соответствует
Cancel при наличии этой кнопки, иначе закрывает уведомление с результатом OK. Клавиши Left/Right/Tab переключают выбор;
Enter/Space подтверждают.

Система хранит одну модальную запись `DialogDescriptor` размером 132 байта (`title[32]`, `message[96]`, `id`, `kind`,
`buttons`), копирует её из VM и валидирует. Новый syscall `graphics` operation **11** открывает диалог. Существующий
`operation_poll=7` возвращает `EventType::DialogResult=4`, `id` диалога и `value` 1/2. Новый `Event` не введён; события
обычного окна во время модального показа подавляются. Второй одновременный диалог не допускается.

`MessageBox::exec()` блокирует только вызывающий цикл `.lexx`, ожидая события через периодический `ui::poll()`. ОС
продолжает работать. Вызывать из `Button::on_click()` допускается. Непосредственный `ui::poll()` можно использовать для
неблокирующих диалогов.

## Layout

По умолчанию `Window::add(Widget&)` добавляет элементы **вертикально**. `Row` группирует соседние элементы
горизонтально:

```cpp
Button ok{1,"OK"}, cancel{2,"Cancel"};
Row actions;
actions.add(ok);
actions.add(cancel);
window.add(actions);
```

SDK кодирует продолжение строки в **бит 2 `Control.flags`** (`flag_same_row=4`), оставляя структурный ABI без изменений.
Геометрию рассчитывает система; размеры столбцов равны с учётом отступов и минимальных размеров контролов. Настоящие
рекурсивные деревья вложенных контейнеров в текущем ABI v1 ещё не представлены, они требуют отдельного форматного
протокола.

## Прокрутка

Когда высота содержимого `Window` превышает LCD, окно не отклоняется: система хранит ограниченный scroll offset,
подсвечивает положение на полосе прокрутки и автоматически смещает видимую область при перемещении фокуса Tab/Up/Down.
Отрисовка целого контрола происходит только тогда, когда он полностью помещается в viewport. Частичные клипы **пока
намеренно не рисуются**, поскольку `DisplayDevice` не предоставляет универсальной операции scissor clipping. Ручная
геометрия не прокручивается. Максимум восемь контролов сохраняется.

## Лимиты и безопасность

- Никаких guest callback pointers и новых указателей в ABI.
- Строки ограничены NUL-terminated массивами и проверяются до копирования.
- Один активный диалог; код события отделён от `Close` обычного окна.
- Графическое владение и фокус проверяются syscall до открытия диалога.
- Для рисования и обращения к LCD используется существующий `DeviceResourceLock`.
- `graphics::Command` и старые `.lexx` сохраняют совместимость.

## Проверка

```bash
cmake --build build/host-full --target lexxos_system_ui_tests lexxos_sim app-ui-demo -j 12
ctest --test-dir build/host-full -R '^lexxos_system_ui_tests$' --output-on-failure
```

В `ui-demo` кнопка **Dialogs** последовательно открывает Information, Warning, Error, Question. На вопрос проверьте
Cancel через Escape, а затем переключение на OK. Кнопка Save открывает информационное сообщение. После закрытия каждого
диалога фокус и содержимое окна должны сохраняться.
