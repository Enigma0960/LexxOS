# LexxOS — чеклист рефакторинга C/C++

**Принцип:** один компонент — одна ответственность — явные зависимости — единый стиль.

### 1. Архитектура

- [ ] **Одна ответственность.** Файл и каждый класс решают одну логически завершённую задачу. Команды, UI, протоколы,
  драйверы и управление ресурсами разделены.
- [ ] **Правильный слой.** Код находится в соответствующем слое:
  `core / kernel / platform / hardware / drivers / devices / services / apps / composition`. Зависимости направлены
  через установленные контракты.
- [ ] **Никаких скрытых зависимостей.** Используются переданные интерфейсы и контекст вместо глобального состояния,
  singleton и прямого обращения к чужим сервисам. Legacy API остаются только там, где необходима совместимость.
- [ ] **Платформенная независимость.** Переносимый код не содержит SDK/MMIO/RTOS-зависимостей. Аппаратные реализации
  находятся в backend, выбор устройств и соединений — в composition.
- [ ] **Явный жизненный цикл.** Владение объектами, буферами, задачами, IRQ и DMA определено. Инициализация, остановка,
  освобождение и восстановление ресурсов безопасны.

### 2. Классы и функции

- [ ] **Один самостоятельный класс — одна пара `.h/.cpp`.** Исключения: небольшие локальные helper-классы и шаблоны,
  которым требуется определение в заголовке.
- [ ] **Заголовки содержат интерфейс.** Нетривиальные реализации вынесены в `.cpp`; используются минимальные `#include`
  и необходимые forward declarations. Связанные структуры допустимо группировать по назначению.
- [ ] **Функции декомпозированы.** Ориентир — до 50–70 строк; свыше 120–150 строк требуется обоснование или разделение.
  Каждая функция выполняет одну понятную операцию.
- [ ] **Файлы имеют разумный размер.** Обычный `.cpp` — ориентир 400–600 строк, алгоритмический — до 800–1000, заголовок
  класса — 200–250. Разделение выполняется по ответственности, не по количеству строк.
- [ ] **Нет дублирования.** Повторяющиеся алгоритмы вынесены в общие компоненты. Platform-specific различия реализуются
  через backend, а не копированием логики.

### 3. Стиль

- [ ] **Единое форматирование.** Соблюдаются `.clang-format` и `.codeunifier.json`; собственный заголовок подключается
  первым, `#include` упорядочены; методы и поля классов логически сгруппированы.
- [ ] **Пространства имён и блоки оформлены правильно.** Закрывающий комментарий содержит полное имя, например
  `} // namespace lexxos::devices::detail`.
  Завершённые блоки отделяются пустой строкой, когда далее следует самостоятельный код; исключения — короткие
  конструкции, где разделение ухудшает читаемость.
- [ ] **Понятные имена и комментарии.** Названия отражают назначение; комментарии на русском объясняют причины,
  ограничения и этапы алгоритма, а не пересказывают код. Нет неиспользуемых элементов.

### 4. Надёжность и переносимость

- [ ] **Ошибки обрабатываются явно.** Результаты операций и причины отказов доступны вызывающему коду; ошибки не
  маскируются молчаливым успехом.
- [ ] **Память и многозадачность безопасны.** Учитываются лимиты MCU, размеры стеков, владение буферами, синхронизация,
  контексты ISR и время жизни асинхронных операций. Нет необоснованных динамических выделений.
- [ ] **Рефакторинг не меняет поведение.** Сохранены публичные API, ABI, команды, аргументы, коды ошибок, форматы
  вывода, feature flags, порядок инициализации и платформенная совместимость.

### 5. Проверка результата

- [ ] **Сборка и тесты проходят.** Проверены доступные host/simulator/firmware-конфигурации и соответствующие contract
  tests. Для аппаратно-зависимых изменений отдельно зафиксирована необходимость hardware-проверки.
- [ ] **Документация и сборочные списки актуальны.** Проверены `CMake`, include/call sites, регистрация команд, тесты и
  документация. Устаревшие адаптеры удаляются только после проверки всех потребителей.

---

## Критерий завершения

Файл считается приведённым к стандарту, когда:

1. Все применимые пункты выполнены.
2. Неприменимые пункты явно отмечены как `N/A`.
3. Исключения обоснованы и задокументированы.
4. Не возникло новых нарушений в соседних компонентах.
5. Выполнены доступные проверки и отсутствуют выявленные регрессии.

**Правило выполнения:** архитектурное разделение, изменение поведения и механическое форматирование выполняются
отдельными патчами.
