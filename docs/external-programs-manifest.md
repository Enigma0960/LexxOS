# Манифесты внешних программ LexxOS

Исходный manifest.json находится в проекте приложения. При упаковке tools/lexx_pack.py проверяет JSON, автоматически добавляет UTC-время сборки и помещает метаданные внутрь .lexx. Данные можно прочитать без запуска программы.

## Пример manifest.json

    {
      "schema": 1,
      "id": "org.example.hello",
      "name": "Hello",
      "version": "1.2.3",
      "description": "Приветствие и проверка терминала",
      "author": "Example Development Team",
      "license": "MIT",
      "contacts": {
        "email": "dev@example.org",
        "website": "https://example.org",
        "repository": "https://example.org/hello.git"
      }
    }

Обязательные поля: schema (целое число 1), id, name, version, author, license (непустые строки).
Необязательные: description (строка), contacts (словарь строк). Версия приложения следует SemVer (MAJOR.MINOR.PATCH и допустимые suffix).
Идентификатор id должен оставаться постоянным от версии к версии и может содержать латинские буквы, цифры, точки, дефисы, подчёркивания.

Значение license нужно брать из фактической лицензии приложения (рекомендуется SPDX).
В демонстрационных проектах указано UNLICENSED: это отсутствие публично предоставленной лицензии, а не свободная лицензия.
Поле build в исходном файле указывать запрещено: его добавляет упаковщик.

## Сборка

    python3 tools/lexx_pack.py app.bin app.lexx --manifest manifest.json --memory 65536 --stack 4096 --cap console,keyboard

Упаковщик автоматически добавит поле с UTC timestamp, например:

    "build": {
      "timestamp": "2026-10-20T00:00:00Z"
    }

Дата выше иллюстрирует формат, а не результат конкретной сборки.
Значение берётся из времени запуска упаковщика. SOURCE_DATE_EPOCH заменяет текущее время для воспроизводимых сборок.
Опция --manifest необязательна: без неё создаётся прежний формат без манифеста.

## Проверка внутри LexxOS

    lexx:/> version
    lexx:/> lexx-info /mnt/sd/apps/hello.lexx
    lexx:/> lexx-info --json /mnt/sd/apps/hello.lexx

Команда version уже показывает версию/дату компиляции самой LexxOS.
lexx-info показывает заголовок выбранной программы (формат, ABI, архитектура, права, память, размер) и полный встроенный JSON.
--json выводит только JSON, что подходит для экспорта и будущих инструментов управления пакетами.
Старые исполняемые файлы получают сообщение manifest: not present (legacy), --json возвращает ошибку.
Команда ни при каких обстоятельствах не запускает исполняемый код.

## Формат бинарного файла

    +-------------------------------+
    | LEXX header v1 (64 bytes)     |
    +-------------------------------+
    | RV32I executable image        | imageSize из заголовка
    +-------------------------------+
    | JSON manifest (UTF-8)         | максимум 4096 байт
    +-------------------------------+
    | "LXMF" (4 bytes)              |
    | length (little-endian u32)    |
    | CRC-32 (little-endian u32)    |
    +-------------------------------+

Зарезервированные поля заголовка остаются нулями. Header v1 и ABI v1 не изменяются: imageOffset/imageSize по-прежнему адресуют только машинный код.
Существующий загрузчик уже допускает данные после image и поэтому может исполнять такие файлы без доработки.

lexx-info проверяет размер и положение JSON (только после образа), CRC-32, читает файл частями по 128 байт.
CRC-32 обнаруживает случайные повреждения, **но не подтверждает подлинность автора** и не является цифровой подписью.
