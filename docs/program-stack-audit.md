# Аудит стеков программ 0.0.7

Имена тестовых файлов и идентификаторы портов в примерах условные; результаты измерений сохранены.

Дата замера: 2026-06-25.
Устройство: ClockworkPi PicoCalc с Raspberry Pi Pico W.
Порт: `/dev/tty.usbserial-XXXX`, 115200 бод.
Прошивка: LexxOS 0.0.7 standard, PicoCalc Pico W.

Методика: команды запускались через supervisor (`run <command>`) или напрямую, если программа уже имеет
`ForegroundTask` профиль выполнения. Значение `used` рассчитано как `stack - free` из `jobs`. Для рабочих сборок нужен
запас не меньше 1024 байт; значения ниже этого запаса помечены как кандидаты на оптимизацию.

## Кандидаты, не покрытые стандартной прошивкой

- `gbemu` не зарегистрирован в стандартной сборке без PSRAM. Основной
  потребитель внешней памяти: `ExternalRequired`, квота 1024 КиБ, стек
  12288 Б. Меню может войти в эмулятор до возврата, нужен запас вложенных TUI-вызовов.
- ESP-IDF ESP-Hosted `wifi-scan` измерен отдельно на `jc_esp32p4_m3_dev`
  после обновления C6 до ESP-Hosted 2.11.7. Общая ESP-IDF-команда использует
  стек 8192 Б; строка 5120 выше относится к диагностике Pico/CYW43.
- `gb-rom-check` в full имеет блочный буфер 512 Б и несколько массивов:
  перед обычным запуском через супервизор перенести буфер в арену.
- `mplayer` выключен по умолчанию; состояние MIDI и массивы дорожек требуют
  аудита до включения в стандартные сборки PicoCalc.

## Политика выполнения

- Сохранять общий минимум супервизора 4096 Б до явных профилей тяжёлых команд.
- Задавать отдельные профили тяжёлой диагностики вместо общего снижения лимитов.
- После аппаратной проверки арен `fs-smoke`, `cp`, `sd-bench` рассмотреть
  стек 3072 Б для простых команд `Inline`.
- Стек и TCB задачи оставлять во внутренней SRAM. PSRAM предназначена для
  рабочих областей, файловых буферов, ROM/кеша и документов редактора.
