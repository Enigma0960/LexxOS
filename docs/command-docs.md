# Документация команд

Справочник конкретной сборки генерируется из двух источников:

- runtime `help` конкретной сборки LexxOS;
- необязательных doc-блоков в `.h` файлах команд.

Shell `help` остаётся обязательной частью каждого сгенерированного Markdown-файла: он показывает фактические
`ProgramDescriptor` и `ProgramArgumentSpec`, которые увидит пользователь в прошивке.
Отключённые команды (`disabled`) в справочник не включаются.

## Генерация для одной сборки

Сначала соберите нужный профиль. Генератор читает плату, платформу, flavor и версию из его `CMakeCache.txt`;
список команд и usage получает из фактической runtime-справки. После изменения feature-флагов обязательно пересоберите
программу: один только CMake configure не обновляет справку бинарного файла.

```sh
python3 tools/generate-command-docs.py \
  --build-dir build/full-host_native --host build/full-host_native/src/lexxos

python3 tools/generate-command-docs.py \
  --build-dir build/full-dev-sim --sim-lib build/full-dev-sim/src/liblexxos_sim.dylib
```

Для Linux замените `.dylib` на `.so`. Host и simulator генерируются отдельно. По умолчанию результат находится
в `<build-dir>/command-docs`; `--output` позволяет выбрать другую папку. Не используйте одну папку для разных профилей.

Для аппаратной сборки сохраните UART transcript из соответствующей прошивки: отключите autosuggest,
выполните `help`, затем `help <name>` для каждой доступной команды, находясь в корневом каталоге shell.
Передавайте только вывод справки, без истории команд и credentials:

```sh
python3 tools/generate-command-docs.py \
  --build-dir build/full-picocalc_pico_w --help-dump build/picocalc-help.txt
```

Генератор проверяет полноту transcript; соответствие прошивки выбранному build-dir проверяет оператор.
Нельзя получить достоверный список команд аппаратной платы, подставив вместо неё host executable.

`docs/commands/` остаётся общим справочником разных реализаций, а не обещанием доступности всех команд на каждой плате.
Для точного набора используйте справочник своей сборки или shell `help`.

## Doc-блок в заголовке

Для расширенного описания добавьте в `.h` файл команды комментарий вида:

````cpp
/**
 * @lexxos-command-doc command-name
 * @source src/lexxos/apps/example/example_program.cpp
 * @description
 * Подробно описывает, что делает команда и в каких сценариях её использовать.
 *
 * @parameters
 * - `--flag` — необязательный флаг.
 * - `--count <n>` — необязательный параметр; по умолчанию `10`; диапазон `1..100`.
 *
 * @examples
 * ```text
 * lexx:/> command-name --count 5
 * ```
 *
 * @author
 * Свободный комментарий автора: ограничения, заметки о железе, осторожность при первичном запуске.
 * @end
 */
````

Разметка секций простая:

- `@lexxos-command-doc <name>` — имя shell-команды;
- `@platforms sim espidf` — необязательный список платформ, для которых подходит блок;
- `@boards picocalc_pico_w picocalc_pico2w` — необязательный список плат; при наличии обоих селекторов должны совпасть оба;
- `@source <path>` — относительный путь к основному исходнику команды;
- `@description` — расширенное описание;
- `@parameters` — параметры, обязательность, значения по умолчанию, допустимые диапазоны;
- `@examples` — примеры использования;
- `@author` — свободный авторский комментарий;
- `@end` — конец блока.

Если doc-блока нет, генератор оставит только runtime help и заметку о доступности.

При нескольких подходящих блоках с одинаковым именем генерация завершается ошибкой с путями исходников.
Порядок обхода файлов не влияет на выбор. Селекторы выбирают расширенное описание, но не добавляют команду,
которой нет в runtime help.

Индекс содержит только команды выбранной сборки. Старые страницы на диске не удаляются, чтобы сохранить ручные
заметки, но не включаются в индекс. Пользовательские секции сохраняются; устаревшие автоматически генерируемые
секции заменяются даже при исчезновении соответствующего doc-блока.

`gpio-analyzer` — экспериментальная программа только для full и поддерживаемых плат. Её интерфейс и поведение
могут меняться; ограничения памяти платы могут исключать её даже из full.
