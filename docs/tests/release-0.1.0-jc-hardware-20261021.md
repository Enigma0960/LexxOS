# JC-ESP32P4-M3-DEV: аппаратная проверка 2026-10-21

Статус: **частичный smoke; выпуск пока заблокирован дефектами ниже**.
Плата с microSD и USB-UART, консоль 115200 8N1.
Внешние LCD/touch, USB HID и Ethernet не подключены; их работа не подтверждена.

## Идентификация образов

- В исходном логе указаны пустая версия и `flavor: standard`. Для проверки
  публичного minimal preset требуется отдельный прогон.
- Исходная прошивка на подключённой плате: повторяющийся reset до shell.
  Точное соответствие её бинарника локальному ELF до перепрошивки не установлено.
- Диагностический full собран из commit
  `2d71173d6697bbc233a08584de8fee40145274bd`, preset `full-jc_esp32p4_m3_dev`,
  MinSizeRel, ESP-IDF 6.0.2. В локальном sdkconfig вывод ESP-IDF перенесён с
  USB Serial/JTAG на UART0 TX37/RX38, 115200. Приложение записано с разрешения автора;
  hash записи проверен esptool. Bootloader, partition table и C6 не прошивались.
- Первый диагностический ELF SHA256:
  `3ad2c42f08500676aa415adbc95fa218dc95baa8be19b3794b09351d9b079fb8`.
- Повторный full содержит только исправление генератора регистрации команд
  поверх указанного commit и ту же диагностическую настройку консоли.
  BIN SHA256: `0a419d6e3547d07fde9d4d41a4a40881076d82ed8af998b3fb0bb949bef55d9c`.
  ELF SHA256: `a77cd564293737a2916c84497c404b6339039d44e033c7fbea7d8a687010e140`.

## Причина сбоя full и исправление

На первом диагностическом образе дважды записан `Stack protection fault` задачи
`main`. PC `0x4802ec36` соответствует `registerBuiltinPrograms()`, MEPC
`0x480416a6` — первому вызову `AppendProgram::descriptor()`.
Стек функции регистрации занимал **9136 байт** (944 + 8192 по дизассемблеру),
при `CONFIG_ESP_MAIN_TASK_STACK_SIZE=8192`. Поэтому full падал до инициализации SD.
Сообщение об отсутствующем touch предшествовало сбою, но не было его причиной.

Генератор теперь создаёт таблицу фабрик дескрипторов и один цикл регистрации.
Один call site повторно использует временный дескриптор. Стек функции в повторном
ELF составляет **176 байт**, размер main stack не увеличивался. После исправления
плата загрузилась до shell и выполнила проверки ниже.

Дополнительная проверка изменения: 9/9 Python-тестов каталога, host minimal build,
full host build и 27/27 CTest. Это не повтор всей матрицы MCU.

## Оставшиеся дефекты

1. **Переполнение стека при `shell-config load`.** На исправленном full задача
   `console` имеет стек 12288 байт. Panic PC `0x48066014`, MEPC `0x48066022`
   соответствуют `historyLineAllowed()` в `shell_history_policy.cpp`, локальному
   буферу токена. SP `0x4ff75b20` ниже границы `0x4ff75db0`. Нужно уменьшить
   вложенные стековые буферы загрузки/фильтрации истории и повторить ручной тест.
2. **Alias `rename` не наследует runtime `mv`.** Его descriptor задаёт
   `MoveProgram::run`, но не копирует runtime с квотой workspace и foreground task.
   Поэтому обработчик получает контекст без арены; прямой `mv` проходит.
3. **Пустая версия ESP-IDF.** `build_info.h.in` использует `PROJECT_VERSION`,
   который пуст в момент генерации внутри ESP-IDF component configure.
   Нужно согласовать генерацию с ESP-IDF `PROJECT_VER` и проверить команду `version`.

Эти три дефекта не исправлены данным прогоном. После их исправления необходимы
повторные full/minimal smoke и обновление статуса release candidate.

## Состояние платы после проверки

После panic повторная проверка подтвердила доступный shell, SD ready и отсутствие
тестового каталога; свободная память 220351 байт. Serial-порт освобождён.

На плате оставлен исправленный диагностический full с выводом panic через UART0.
