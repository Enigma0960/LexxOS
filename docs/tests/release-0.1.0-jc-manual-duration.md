# JC ESP32-P4: ручные проверки продолжительной работы

Имена тестовых файлов и идентификаторы портов в примерах условные; результаты измерений сохранены.

Эти сценарии **не выполнялись автоматически**. Их запускает автор после короткой
регрессии на выбранной прошивке. Производительность гостевых приложений не является
критерием приёмки: проверяются загрузка формата, исполнение, выход и освобождение ресурсов.
Статус: отложены автором. Единичный reset предыдущего прогона принят как
неблокирующее наблюдение; эти сценарии также помогут накопить статистику.
Его предварительное устранение не является условием запуска.

## Область обязательного регресса

Ядро, UART shell, SD/VFS, загрузка shell-config, доступная сеть и загрузчик `.lexx`.
Game Boy, MIDI, GPIO analyzer, экспериментальные режимы процессов и аппаратные
пробы не входят в этот прогон. Внешние устройства проверяются отдельно и не
требуются для прохождения базового регресса.

По сообщению автора ранее минимально проверены: экран работает, звук есть,
внешняя клавиатура работает. Это отдельное ручное свидетельство, не результат
текущего автоматического прогона и не полная приёмка всех режимов периферии.
На текущей плате подключён Ethernet, остальная внешняя периферия отсутствует.

## Подготовка

Сохранить UART-лог, `version`, `storage`, `net-status`, `mem`, `tasks`, `uptime`.
Записать дату, профиль и build timestamp. Не подменять идентификацию установленной
прошивки commit текущего checkout без отдельного подтверждения.

В командах ниже используется `/mnt/sd/stability-test`. Сначала выполнить
`stat /mnt/sd/stability-test`. Продолжать только если каталог отсутствует;
если существует — выбрать новое имя и заменить его во всём сценарии.

```text
mkdir /mnt/sd/stability-test
echo sample-data > /mnt/sd/stability-test/original.txt
sync
cat /mnt/sd/stability-test/original.txt
```

## Нагрузка SD + сеть: 60 минут

После установления сети снять исходные `mem`, `tasks`, `uptime`. Каждый раз
дожидаться возврата prompt. Повторять блок примерно раз в минуту в течение часа:

```text
cp /mnt/sd/stability-test/original.txt /mnt/sd/stability-test/copy.txt
rename /mnt/sd/stability-test/copy.txt /mnt/sd/stability-test/moved.txt
cat /mnt/sd/stability-test/moved.txt
rm /mnt/sd/stability-test/moved.txt
sync
shell-config load
mem
```

Добавлять `ping --count 3 <gateway>` с фактическим gateway из `net-status`.
Каждые десять минут сохранять `tasks`, `uptime`, `net-status`, `storage`.
Если Wi-Fi и Ethernet подняты одновременно, обычный ping не доказывает выбор
конкретного интерфейса; без отдельного контроля маршрута отмечать «активная сеть».

PASS: данные совпадают, команды завершаются, нет незапрошенных reset, зависаний,
ошибок SD и устойчивого падения свободной памяти после прогрева. Колебания heap
с возвратом допустимы; при снижении сравнить несколько следующих замеров в одинаковом
состоянии. Известные автору потери ping допустимы, если сеть не блокирует shell
и нет явного сбоя backend платы. Не требовать 100% ответов в этой сети.

## Простой: 2–8 часов

Оставить плату в shell с обычными сохранёнными настройками. В начале и конце,
при возможности ежечасно, выполнить `uptime`, `mem`, `tasks`, `storage`, `net-status`.
В конце прочитать `original.txt`. PASS: uptime не сбросился, файл сохранён,
shell доступен, нет необъяснимого роста числа задач и прогрессирующего расхода памяти.
Не менять RTC/NTP и не отключать питание ради этого сценария.

## Повторные запуски `.lexx`: 20 циклов

Использовать четыре программы из релизного apps ZIP в `/mnt/sd/lexx`. Перед началом сохранить `lexx-info` для
каждого файла и `mem`. В каждом цикле запускать по очереди:

```text
/mnt/sd/lexx/fileman.lexx /mnt/sd/stability-test /mnt/sd
/mnt/sd/lexx/pacman.lexx
/mnt/sd/lexx/snake.lexx
/mnt/sd/lexx/tetris.lexx
```

В программах дождаться первого экрана и нажать `q`; дождаться prompt и проверить,
что строка ввода пуста. Игровой процесс, FPS, звук и физический ввод не оцениваются.
Операции записи в UI fileman не выполнять. После каждого приложения
выполнить `echo returned`, `mem`; после полного цикла — `tasks`.
PASS: каждый запуск и выход успешен, память после завершения
возвращается к стабильному уровню. Ошибка загрузчика, invalid instruction, утечка,
reset или невозможность вернуться в shell — FAIL. Ctrl+C считать отменой, а не
подтверждением штатного выхода приложения.

## Завершение и сохранность

```text
sync
reboot
```

После появления shell проверить `version`, `cat /mnt/sd/stability-test/original.txt`,
`storage`, `net-status`, `mem`, `tasks`. Удалять только файлы, созданные сценарием:

```text
rm /mnt/sd/stability-test/original.txt
rmdir /mnt/sd/stability-test
sync
stat /mnt/sd/stability-test
```

Если `rmdir` сообщает о непустом каталоге, посмотреть `ls` и удалить только известные
остатки `copy.txt`/`moved.txt`; не использовать рекурсивное удаление неизвестных данных.
При сбое сохранить лог, последний успешный шаг, время/uptime, память и reset reason;
остановить сценарий. Итог оформить отдельно для каждого теста: PASS/FAIL/не выполнен,
фактическая длительность, число циклов, исходная/конечная heap и приложенные логи.
