# LexxUI S5.3.1 — независимые системные контролы

Этот этап реорганизует **реализацию
LexxUI в ядре** и не добавляет гостевые syscalls, не меняет `ui/core.h`
и не требует пересборки существующих `.lexx` программ.

## Модель ответственности

- `src/lexxos/ui/guest_ui_types.h` — только ABI-структуры `Control`,
  `Document`, `Event`, `ListItems`, фиксированные размеры и `static_assert`.
- `guest_ui_theme.h` — константы системной палитры; индивидуальные контролы
  не определяют собственную тему оформления.
- `guest_ui_text.h` — UTF-8 decoding, поиск глифа и общий RGB565-рендерер
  системного шрифта. Встроенный шрифт остаётся в
  `noto_sans_mono_9x16.h`.
- `controls/common.h` — общий контракт `Handler` и примитивы оформления
  панели, текста и шкалы; без зависимости от другого контрола.
- `controls/<тип>.h` — рендеринг, нормализация значения и обработка клавиш **одного** типа. Каждый файл можно подключать
  независимо.
- `controls/registry.h` — фиксированная `constexpr` таблица обработчиков,
  индексируемая **неизменяемым числовым** `Control.kind` (1..7).
- `guest_ui.h` — `GuestView`: валидирует документ, управляет системным
  фокусом, хранит значения, запускает кадр, вызывает методы обработчиков.

```
.lexx (lexx::ui::Window / Button / ...)
     │ неизменённый ABI (Document, Control, Event)
     ▼
VM graphics syscall → GuestView → controls::registry
                                      ├─ label.h
                                      ├─ button.h
                                      ├─ checkbox.h
                                      ├─ text_field.h
                                      ├─ progress_bar.h
                                      ├─ slider.h
                                      └─ list_view.h
                                             │
                                    DisplayDevice RGB565
```

## Контракт системного обработчика

Для каждого вида контрола предусмотрен неизменяемый экземпляр `Handler` с:

- `render(DisplayDevice&, Control const&, ListItems const&, selected)` —
  отрисовка; не изменяет состояние и не управляет `beginFrame/endFrame`;
- `key(Control&, ListItems const&, KeyCode, char, Event&, dirty&)` —
  только собственная логика ввода, обновление состояния и событий;
- `normalize(Control&, itemCount, configuring)` — ограничение значений.
  Флаг `configuring` отличает исходное объявление контрола от последующего
  обновления: первоначальное `ListView.value` нельзя обнулять до `setItems()`;
- `defaultHeight`, `minimumWidth`, `minimumHeight`, `focusable`,
  `usesListItems`, `verticalNavigation` — параметры размещения/фокуса.

В таблице нет динамических аллокаций, RTTI, виртуальных классов виджетов
или пользовательских callback-указателей. Строки и значения по-прежнему
хранятся в системной копии документа, а не в памяти `.lexx`.

Общие реакции `Escape` (закрыть), `Tab` (переместить фокус), а также
навигация Up/Down для обычных контролов принадлежат `GuestView`.
`ListView` перехватывает Up/Down только при наличии элементов и не
переключает фокус на границе списка. Его обработчик является единственным,
которому передаются актуальные элементы `ListItems`.

## Совместимость

| Контракт                                         | S5.3.1                   |
|--------------------------------------------------|--------------------------|
| `Control`                                        | 48 байт — без изменений  |
| `Document`                                       | 420 байт — без изменений |
| `Event`                                          | 40 байт — без изменений  |
| `ListItems`                                      | 260 байт — без изменений |
| `Control.kind`                                   | 1..7 — без изменений     |
| Syscall, manifest, графическая capability        | Без изменений            |
| LexxUI SDK классы и старый процедурный интерфейс | Без изменений            |
| Системная палитра, Noto Sans Mono и размер глифа | Без изменений            |

Это **структурный рефакторинг**, а не добавление новых видов контролов.
Системные цвета, отступы, сценарии ввода и отрисовки сохраняются.

## Добавление нового вида контрола в будущем

1. Добавить независимый `src/lexxos/ui/controls/my_control.h`, зависящий
   только от `controls/common.h`.
2. Реализовать три операции `render`, `key`, `normalize` и дескриптор `handler`.
3. Зарегистрировать его в `controls/registry.h` под **новым** значением kind;
   старые kind и ABI-структуры не переупорядочивать.
4. Добавить типизированную обёртку в `apps/sdk/lexx/ui/my_control.h`,
   не требующую включения чужих виджетов.
5. Добавить регрессионные тесты ввода, геометрии и framebuffer.

Не добавлять новый `if (kind == ...)` в `GuestView`, если поведение можно
описать метаданными обработчика. Layout, оконный менеджер и входные устройства
будут развиваться независимо от конкретных виджетов.

## Проверка

```bash
cmake --build build/host-full --target lexxos_system_ui_tests lexxos_sim -j 12
ctest --test-dir build/host-full -R lexxos_system_ui_tests --output-on-failure
```

Далее перезапустить эмулятор, открыть старый `ui-demo.lexx`, проверить
`Tab`, `Space`, стрелки, Enter, редактирование TextField, выбор ListView,
Slider ↔ ProgressBar, закрытие Escape. Повторить на PicoCalc Lyra.
