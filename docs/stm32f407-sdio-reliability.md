# Надёжность SDIO на STM32F407

Этап расширяет первичный запуск SDIO неразрушающей диагностикой и тестами чтения/записи через FAT.

## Команды

```text
storage
storage probe
storage read0
storage read <block>
storage diag
sd-test [path]
sd-bench [blocks] [path]
sd-stress [passes] [files]
```

## Последовательность проверки

```text
storage
storage diag
storage read 0
storage read 8192
sd-test
sd-bench
sd-stress
fs-info
fat-cache
sd-debug
mem
tasks
```

`sd-bench` по умолчанию использует 128 блоков, то есть 64 КиБ. Команда измеряет сырое чтение SD, записывает временный
FAT-файл, читает его обратно с проверкой шаблона и удаляет.

`sd-stress` по умолчанию выполняет три прохода по четыре файла. На каждом проходе создаются, проверяются и удаляются
FAT-файлы размером 512 байт.

## Ограничения

Тесты не выполняют сырую запись блоков. Все проверки записи идут через VFS/FAT и используют временные файлы в
`/mnt/sd`.

Текущий SDIO backend работает в polling-режиме и ориентирован на одиночные блоки. DMA и multi-block transfer следует
оптимизировать только после стабильной аппаратной проверки базового пути.

## Память STM32F407

На STM32F407 функция Game Boy по умолчанию отключена, пока стабилизируются SDIO и дисплей. Это удерживает образ в
пределах основной SRAM объёмом 128 КиБ.

Экспериментальная сборка:

```bash
cmake --preset debug-stm32f407 -DLEXXOS_ENABLE_GAMEBOY=ON
```

Для устойчивой работы такого профиля потребуется отдельный план памяти: workspace эмулятора, framebuffer и SD/FAT
runtime конкурируют за одну SRAM.
