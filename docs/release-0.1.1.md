# LexxOS 0.1.1

Изменения относительно [публичного prerelease 0.1.0](https://github.com/Enigma0960/LexxOS/releases/tag/v0.1.0).
Выпуск добавляет прошивку для PicoCalc с Luckfox Lyra M, SDK LexxCE для ESP32
и графический SDK для приложений `.lexx`.

## Состав выпуска

| Компонент                 | Поставка                                                                                                  |
|---------------------------|-----------------------------------------------------------------------------------------------------------|
| Прошивки из 0.1.0         | 12 архивов minimal/full для Cardputer ADV, PicoCalc с Pico, Pico W, Pico 2 и Pico 2 W, JC ESP32-P4-M3-DEV |
| PicoCalc / Luckfox Lyra M | Один архив `picocalc-lyra-release` с FreeRTOS и JCS, ядром и инструментами сборки FIT и обновления        |
| Гостевые приложения       | Fileman, Pacman, Snake и Tetris в одном ZIP                                                               |
| LexxCE                    | Один SDK ZIP для классического ESP32                                                                      |

Всего 15 ZIP, общий `SHA256SUMS` и `release.json`. Демонстрации SDK и LexxUI
и примеры `hello`/`cat` доступны в исходниках. [Состав архивов и установка](release-packaging.md).

## Изменения с 0.1.0

- **PicoCalc / Luckfox Lyra M.** Добавлен профиль с FreeRTOS, управляемой MMU и
  DMA для LCD и чтения съёмной карты. Съёмная `sd1` монтируется с чтением и
  записью, извлечение и повторная установка обрабатываются автоматически.
  Загрузочная `sd0` доступна для ручного монтирования с политикой read-only по
  умолчанию. На LCD доступны часы, индикатор батареи и выключение по тайм-ауту.
  [Руководство Lyra](boards/picocalc_lyra_m.md).
- **LexxCE для ESP32.** SDK включает публичные заголовки и статические
  библиотеки ядра, порта ESP-IDF и двух режимов исполнения — cooperative и
  FreeRTOS. Добавлены именованные цифровые входы и выходы, I²C, SPI, ADC/PWM
  и DAC. В комплекте шесть автономных примеров. Собственный проект подключает
  описание периферии через `LegacyBoardDescriptor`.
  [Руководство SDK](../ce/README.md).
- **Пакеты CMake.** Внешний проект может подключить `LexxSDK` для встроенных
  программ, `LexxAppSDK` для приложений `.lexx` или `LexxCE` для собственной
  прошивки на ESP32. [Подключение через find_package](cmake-packages.md).
- **Shell и автозапуск.** Команды `link` и `autostart` управляют ярлыками и
  автозапуском приложений. `info` показывает сведения о ярлыке и его цели.
  [Команда link](commands/link.md) · [Команда autostart](commands/autostart.md).
- **Cardputer ADV и PicoCalc Pico W.** На Cardputer увеличен стек команд,
  изменяющих файлы на SD или запрашивающих статус сети. В профиле `full`
  уменьшен кэш чтения FAT, чтобы оставить память для запуска Wi-Fi.
  На Pico исправлены порядок запуска UART, загрузка истории shell с SD и
  выделение памяти для запуска `.lexx`. YMODEM получает исключительный доступ
  к вводу терминала. LexxCP пропускает текстовую диагностику при ожидании
  подтверждений пакетов.
- **YMODEM на Lyra M.** UART передаёт двоичные пакеты без преобразования
  переводов строк. FreeRTOS принимает байты по прерываниям в очередь, вмещающую
  полный пакет на скорости 1 500 000 бод.
- **Гостевой SDK и ввод.** Приложения используют общую статическую среду RV32I.
  Манифест может выбрать клавиатурные события или терминальный ввод. Версии
  формата `.lexx` и RV32I ABI остались равны 1. Старые пакеты с нулевыми флагами
  сохраняют прежний режим ввода. Пакеты с новым флагом требуют его поддержки
  в ОС. [Манифесты и совместимость](external-programs-manifest.md).
- **Графика и LexxUI.** В SDK появились команды рисования, изображения LXIM,
  потоковое чтение ресурсов и спрайтовая анимация. LexxUI добавляет системные
  окна, навигацию по фокусу, вкладки, списки и частичную перерисовку. В симуляторе
  исправлены обработка Tab и закрытие с работающей гостевой программой.
  [ABI графики](external-programs-graphics-abi.md) · [LexxUI](lexxui-system-architecture.md).
- **Архитектура.** Описания плат, регистрация устройств и профили памяти
  перенесены в соответствующие платформенные конфигурации. Runtime получил
  явные зависимости от сервисов ввода, событий и файловой системы.
  [Архитектура ОС](architecture.md) · [Профили памяти](runtime-memory-profiles.md).

## Известные ограничения

- На Lyra M пока недоступен вывод звука. Для обновления требуется совместимая
  загрузочная карта и шаблон FIT владельца. Архив Lyra не содержит полного
  образа карты или компонентов загрузчика поставщика.
- На более ранней сборке Lyra M команда `sd-bench --write` вызвала переполнение
  стека. На сборке от 23:39:47 проверен режим чтения `sd-bench`. Режим `--write`
  повторно не проверяли.
- PicoCalc рассчитан на JCS southbridge. На RP2040 часть тяжёлых возможностей
  ограничена доступной SRAM. В профиле PicoCalc Pico W full кэш чтения FAT
  уменьшен до двух секторов, чтобы прошивка помещалась в SRAM. Для обоих профилей Pico/Pico 2 без W Wi-Fi
  недоступен по аппаратной конфигурации.
- На проверенных PicoCalc с Pico W и Pico 2 W отдельные ошибки чтения FIFO клавиатуры
  появлялись в журнале UART и иногда смешивались с выводом shell.
- Для Hosted Wi-Fi на JC требуется совместимая прошивка ESP32-C6. В `full` 0.1.1
  `net-status` и `wifi-status` вызвали `SW_CPU_RESET` при запросах вскоре после
  загрузки. Отложенный `wifi-status` запустил Wi-Fi и вернул статус. Подключение
  к сети и остаточный UART-ввод после выхода из игр требуют отдельной проверки.
  [Протокол 0.1.0](tests/release-0.1.0-validation.md#аппаратные-проверки-jc-до-финальной-упаковки).
- Бинарный CE SDK предназначен для классического ESP32 и совместимых версий
  ESP-IDF, компилятора и параметров FreeRTOS, указанных в `sdk.json`.

## За пределами базовой приёмки

- Длительные тесты на стабильность и совместную нагрузку SD, LCD и сети,
  замеры производительности, игрового процесса и предельных размеров памяти.
- Game Boy, MIDI, GPIO analyzer и прочие экспериментальные команды и режимы.
- Внешняя периферия и все сценарии работы CE на физическом оборудовании,
  кроме отдельно записанных автором наблюдений.
- Установка Lyra с нуля на пустую SD и холодный старт с полного образа карты.
  Релизный ZIP рассчитан на обновление совместимого загрузочного носителя.
- Сплошная проверка приложений `.lexx` из сторонних источников и точных временных
  характеристик MCU в симуляторе.

Для финального аппаратного прогона используется [короткий ручной регресс](tests/release-0.1.0-manual.md)
с профилем, commit и результатом по каждой плате. Для Lyra в него входят отдельная
проверка `sd1`, управление LCD и возврат из `.lexx` в shell.
