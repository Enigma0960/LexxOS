# Модель ввода внешних программ

Цель: пользовательский код внешней программы не должен знать, откуда пришёл ввод — с аппаратной клавиатуры PicoCalc/Cardputer или из UART-консоли.

На уровне guest SDK основной интерфейс ввода — `lexx::poll_key()`:

```cpp
lexx::KeyEvent event;
if (lexx::poll_key(event)) {
    // event.character содержит ASCII-символ, если он есть
}
```

`lexx::poll_key()` сначала опрашивает событийную очередь клавиатуры через `poll-key-event`. Если событий нет, SDK дополнительно опрашивает текстовый console input через `read-char` и синтезирует `KeyEvent` типа `KeyDown`.

Это даёт единое поведение для первого ABI:

- аппаратная клавиатура приходит как настоящий `InputEvent`;
- UART-символы тоже становятся `KeyEvent` для guest-кода;
- `Ctrl+C` из UART обрабатывается через `read-char` как cancellation;
- `Ctrl+C` с аппаратной клавиатуры обрабатывается через `poll-key-event` как cancellation.

Важно: это текущий guest-facing слой совместимости. Следующий архитектурный шаг — вынести маршрутизацию всех источников ввода в общий runtime input-router, чтобы не только `.lexx`, но и все foreground-программы получали ввод через один и тот же backend.

## Tab completion для прямого запуска `.lexx`

Первый токен shell-команды теперь считается путём, если он:

- пустой;
- начинается с `/`;
- начинается с `.`;
- содержит `/`.

Поэтому такие формы должны дополняться как путь, а не как имя зарегистрированной программы:

```text
lexx:/> /mnt/sd/ext/he<Tab>
lexx:/> ./he<Tab>
lexx:/> ext/he<Tab>
```
