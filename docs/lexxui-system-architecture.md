## Архитектурное решение

**Виджеты отрисовываются и обрабатываются ядром LexxOS.** Приложение `.lexx`
передаёт структурированное описание окна и получает только семантические
события (`Activate`, `Change`, `Close`). Рендерер, тема, шрифт, фокус и
обработка клавиатуры находятся в `src/lexxos/ui/`. Это не встраиваемый GUI
фреймворк в каждое приложение и не отдельный оконный менеджер.

Компоненты:

1. `apps/sdk/lexx/ui.h`: компактный переносимый ABI и обёртки `show/poll/close`.
2. `src/lexxos/ui/guest_ui.h`: валидатор, модель окна, управление фокусом,
   keyboard dispatch и нативная отрисовка стандартной темой.
3. `src/lexxos/ui/noto_sans_mono_9x16.h`: встроенные 1-bit glyphs для текста
   UTF-8 (ASCII 0x20..0x7E и русская кириллица А..я, Ё/ё).
4. `tools/lexx_font_pack.py`: генерация `.h` из TTF/OTF посредством FreeType,
   доступного через Pillow **только на компьютере сборки**.
5. `apps/ui-demo`: отдельное диагностическое `.lexx`, использующее системное окно.

`graphics` syscall 25 расширен операциями (старые номера 0..5 сохранены):

| Operation | Аргументы                   | Результат                                      |
|-----------|-----------------------------|------------------------------------------------|
| 6         | guest pointer на `Document` | 0 при успешном показе окна                     |
| 7         | guest pointer на `Event`    | 1 событие, 0 нет событий, отрицательная ошибка |
| 8         | без аргументов              | закрыть окно, освободить graphics lease        |

Для 6/8 требуется `graphics`; для 7 также `keyboard`. Фокус и владение дисплеем
проверяются ядром. Память дескриптора копируется из гостевого адресного
пространства только после проверки диапазона; в структуре нет указателей.
Размеры ABI фиксированы (`Control=48`, `Document=420`, `Event=40`).
В первой версии допускается 8 контролов, фиксированные пиксельные координаты.
`kind` 1=Label, 2=Button, 3=Checkbox, 4=TextField. `flags` бит0 — disabled.
Все строковые поля ограничены 31 байтом UTF-8 + `\0`. Идентификаторы >0
и уникальны в пределах одного окна.

### Поведение

- `Tab` и стрелки вверх/вниз меняют фокус; Enter/Space активируют кнопку,
  переключают checkbox; Escape закрывает окно; Backspace удаляет символ в
  TextField. На текущем этапе редактирование ограничено печатным ASCII, но *отображение* строк поддерживает кириллицу
  UTF-8.
- `Event` содержит `id`, `type`, `value` и строковое значение редактора.
- При отсутствии событий повторная отрисовка не выполняется.
- Полная перерисовка используется только при `show` и при изменении фокуса/
  значения. Dirty-region redraw остаётся следующей оптимизацией.
- Нативный системный UI не вызывает FreeType и не обращается к SD на каждом кадре.
- `ui-demo` задаёт координаты под 320x320. Более компактный автоматический
  layout и поддержка малых дисплеев — отдельный этап.

## Шрифты и лицензирование

В качестве базового выбран **Noto Sans Mono**, проект Noto, лицензия **SIL Open Font License 1.1**. Это свободная, но
*не* «безлицензионная» гарнитура.
Производный растровый набор распространяется с указанием авторства и текстом
`docs/licenses/NotoSansMono-OFL-1.1.txt`. Исходный TTF в репозиторий не
включён. Наличие лицензии и прав на конвертацию стороннего шрифта является
ответственностью сборщика/распространителя.

Source: https://github.com/google/fonts/tree/main/ofl/notosansmono
License: https://github.com/google/fonts/blob/main/ofl/notosansmono/OFL.txt

**Воспроизводимая генерация:**

```sh
python3 -m pip install Pillow
python3 tools/lexx_font_pack.py NotoSansMono-Regular.ttf \
  src/lexxos/ui/noto_sans_mono_9x16.h \
  --size 13 --cell 9x16 \
  --chars 'U+0020-U+007E,U+0401,U+0410-U+044F,U+0451'
```

Поддерживаются произвольные TTF/OTF и наборы Unicode-диапазонов. Генератор
использует FreeType через Pillow и создаёт таблицу `codepoint -> [16 row masks]`
в C++ header. Рендереру не нужны SVG, FreeType, PNG, TTF или динамические
аллокации. Один глиф — 16×16 бит, Unicode lookup — бинарный поиск по таблице.

### Внешние шрифты — следующий этап, пока не реализовано

Разрешить приложению запрашивать системные именованные шрифты и подключаемые
растровые фонты из `.lexx` ресурсов `:/fonts/...` либо обычной VFS. Загрузка,
валидация и кэширование принадлежат ОС, а не гостю. Конвертер будет расширен
выводом бинарного контейнера `LXFNT` с версией, метриками, Unicode cmap,
объёмом данных и CRC32. Важно ограничить расход кэша, не использовать лимит
двух дескрипторов LXIM, запретить чтение шрифтов с SD при каждом рисовании.
В первом срезе `ui-demo` использует только системный шрифт.

- **S5.2 (текущий):** простой системный vertical auto-layout, `ListView`,
  `Slider`, `ProgressBar`, обновление контролов без сброса фокуса, PRNG в SDK.
  Подробности: [LexxUI S5.2](lexxui-s52-layout-controls.md).
- **S5.3:** системный text layout (метрики, перенос, clipping, выравнивание),
  загрузка дополнительных шрифтов из `.lexx` и VFS, кеш и font-family handle.
- **S5.4:** layout manager, диалоги, combobox, scroll, иерархия виджетов,
  темы оформления и доступность.
- **S5.5:** независимый input-router для клавиатуры, touch, мыши и gamepad;
  централизованные события `Focus/Blur/Click/Change`, безопасный системный
  RNG только при доступной надёжной энтропии, config/storage API.

  расширения памяти VM, Unicode layout, HTTP/TLS, HTML/CSS.

## Ограничения безопасности и производительности

- ABI проверяет диапазоны указателей, NUL-терминацию строк, размеры и типы
  контролов, уникальность ID. Гостевой код не получает указатель на дисплей.
- UI работает только для активного foreground процесса, под существующим
  graphics lease и resource lock; при завершении VM ресурсы освобождаются.
- Никаких callback-адресов гостевого кода внутри ОС; события возвращаются
  явно через `poll()`.
- Система отвечает за общий стиль и масштабирование темы; первое издание
  использует строго фиксированную системную тему и геометрию 320x320.
- `poll()` возвращает сразу; приложение должно использовать `sleep_ms()` или
  `yield()` вместо активного busy loop.
- Сложные игры вправе использовать напрямую `graphics.h`; `ui.h` — отдельный
  высокоуровневый режим, не замена низкоуровневому графическому API.

## S5.3: объектный интерфейс гостевого SDK (обратно совместим)

`apps/sdk/lexx/ui.h` теперь служит удобным единым include для типизированных
виджетов. Исторический процедурный интерфейс (`show`, `poll`, `set_items`,
`update_control`, `close`) находится в `apps/sdk/lexx/ui/core.h` и сохраняется
без изменения номеров системных операций и структуры ABI.

Каждый тип контролов находится в собственном заголовке:

| Файл                | Класс         | Назначение                                                          |
|---------------------|---------------|---------------------------------------------------------------------|
| `ui/window.h`       | `Window`      | Сборка окна из ссылок на объекты, цикл событий, маршрутизация по ID |
| `ui/widget.h`       | `Widget`      | Общая модель, геометрия, состояние disabled, связь с ОС             |
| `ui/label.h`        | `Label`       | Неинтерактивная подпись                                             |
| `ui/button.h`       | `Button`      | Событие `on_click`                                                  |
| `ui/text_field.h`   | `TextField`   | Локальное состояние текста, `on_change`                             |
| `ui/checkbox.h`     | `Checkbox`    | Состояние bool, `on_change`                                         |
| `ui/list_view.h`    | `ListView`    | Варианты, выбор, `on_change` и `on_activate`                        |
| `ui/slider.h`       | `Slider`      | Значение 0..100, `on_change`                                        |
| `ui/progress_bar.h` | `ProgressBar` | Значение 0..100, без событий                                        |

Классы виджетов зависят только от `Widget` и `core.h`, но **не друг от друга**.
`Window` знает лишь о базовом `Widget`; `ui-demo` не анализирует `Kind` и не
содержит сопоставлений `event.id` с числами. Вместо них он привязывает
функции-обработчики к соответствующим объектам.

Приложение владеет временем жизни виджетов; `Window` хранит на них ссылки и
не выделяет память для объектов. По завершении окна `Widget::deactivate()`
сбрасывает связь с ОС. Стековые виджеты должны жить не меньше окна.
Функции обработчиков имеют явный `void* context` и не требуют `std::function`,
кучи, RTTI или исключений. Изменения свойств после `show()` передаются через
прежний syscall `operation_update=9`; список — через `operation_set_items=10`.

Старые приложения с `#include <lexx/ui.h>` и процедурными вызовами продолжают
собираться без правок; перенос низкоуровневых структур из заголовка в
`ui/core.h` не меняет бинарный ABI (`Control=48`, `Document=420`, `Event=40`,
`ListItems=260`). Код UI продолжает отрисовываться только системной частью ОС.

**Границы этапа:** существующая системная реализация обработчиков в
`src/lexxos/ui/guest_ui.h` пока монолитна. Объектная модель этого патча
относится к SDK. Выделение независимых классов контролов со стороны ОС
следует делать отдельным следующим рефакторингом, сохраняя текущий ABI.

См. также [документацию SDK](../apps/sdk/README.md).
