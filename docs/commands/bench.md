# `bench`

Комплексный промежуточный тест с потоковым TSV-отчётом в консоль и, если
доступно, в файл. Актуально на 30 октября 2026.

## Прогоны

```text
bench --profile quick --no-save --no-display
bench --profile quick --device sd1 --no-save --no-display --no-mirror
bench --profile full --device sd1 --no-save
bench --profile soak --duration 300 --device sd1 --no-save
bench --profile vm --iterations 2000 --no-save --no-display --no-mirror
bench --profile vm --iterations 10000 --no-save --no-display --no-mirror
bench --profile vm-detail --iterations 10000 --vm-case load. --vm-repeat 3 --no-save --no-display --no-mirror
bench --profile vm-detail --iterations 10000 --vm-case mix. --vm-repeat 3 --no-save --no-display --no-mirror
```

Начинать на Lyra/FreeRTOS следует с первой команды. `full` добавляет математику,
RTOS-примитивы, worker tasks и заполнение области экрана. `soak` повторяет полный
набор до заданного времени; проверка времени и отмены выполняется между этапами,
поэтому начатый этап может выйти за предел длительности. Запросы SD проверяют отмену
между чтениями. `--no-display` пропускает графические/консольные тесты, но обычный
вывод отчёта по-прежнему использует текущий console output. Для UART-прогона
без текстового LCD mirror добавьте `--no-mirror` вместе с `--no-display`; по выходе
из команды mirror возобновляется; режим Text/Graphics продолжает определяться focus. Сохранение в файл и UART вывод
продолжают работать. Уже передаваемый кадр может завершиться.

## Настройки

### RK3506: экспериментальные атрибуты памяти

`LEXXOS_RK3506_MMU_NORMAL_NC=ON` (по умолчанию OFF) устанавливает
на CPU0 короткую таблицу MMU с тождественным отображением:
DDR 0x00000000..0x07FFFFFF (128 МиБ) — Normal Non-cacheable,
остальные адреса — Shareable Device / XN.
D-cache **остаётся выключенным**. Это эксперимент только для
PicoCalc/Lyra M с 128 МиБ DDR, а не универсальная карта RK3506.

Мотивация: при `SCTLR.M=0` ARMv7-A назначает data access тип
Strongly-Ordered, и это существенно ограничивает пропускную
способность обычного кода, даже при включённом I-cache.

При `ON` под таблицу выделяется 16 КиБ статической `.bss`; при
`OFF` дополнительная память не требуется. Вариант `ON` меняет
поведение всех DDR-обращений, включая FreeRTOS и DMA-клиентов,
поэтому перед использованием на устройстве необходимы проверки
IRQ, UART, SD, LCD, SWD и полной последовательности загрузки.
Гарантии ускорения или полной аппаратной совместимости нет.

Подготовка GDB RAM reload при `ON` сначала отключает MMU,
пока D-cache выключен, затем инвалидирует I-cache. В целях
безопасности при включённом D-cache reload по-прежнему запрещён.

Порядок сравнения: собрать и проверить обычный вариант `OFF`,
затем вариант `ON` с неизменными параметрами `LEXXOS_VM_PROFILE`,
`LEXXOS_VM_LOCAL_PC`, `LEXXOS_RK3506_VM_OPTIMIZATION_LEVEL`.
В логе SCTLR ожидаются `MMU=1, D-cache=0, I-cache=1`, если
`LEXXOS_RK3506_ICACHE=ON`. Сначала выполнить VM-тесты, затем
проверки периферии и SWD.

Для Lyra доступен отдельный профиль `vm`, проверяющий
production RV32I interpreter без файлового и графического I/O.
Количество итераций по умолчанию — 2000, чтобы диагностический
запуск не занимал несколько минут.

Оптимизация интерпретатора управляется
`LEXXOS_RK3506_VM_OPTIMIZED`, а инструкция-кэш —
`LEXXOS_RK3506_ICACHE`. Оба параметра по умолчанию ON.
Для сравнения с прежней конфигурацией их можно отключить.

Уровень оптимизации RV32I VM выбирается через
`LEXXOS_RK3506_VM_OPTIMIZATION_LEVEL=2|3`.
При включённом `LEXXOS_RK3506_VM_OPTIMIZED` по умолчанию
используется `-O3`; `2` возвращает прежний `-O2`.

Дополнительно профиль vm измеряет два host-side сценария,
скомпилированных в том же файле, что и интерпретатор:
`host-reg` (арифметика без volatile-записей в цикле)
и `host-ddr-rmw` (одно volatile-чтение и запись слова на итерацию).
Это диагностические итерации, а не RV32I-инструкции.
Поэтому их `iter/s` нельзя напрямую сравнивать с `inst/s`.

Общий параметр `LEXXOS_VM_PROFILE` поддерживает:
`auto`, `compact`, `fast`, `cached8`, `cached16`.
`auto` выбирает `compact` для Pico/STM32F4 и `fast` для
RK3506/host/sim/ESP-IDF.
`compact` сохраняет исходный исполнительный цикл без кэша.
`fast` использует оптимизированный цикл и единый ALU writeback,
не выделяя дополнительный буфер.
`cached8`/`cached16` добавляют экспериментальный кэш декодирования
на 128/256 байт на VM. Кэш всегда сравнивает текущее исходное
слово инструкции, сохраняя корректность self-modifying code.
На системах с отключённым D-cache он может снижать скорость.
Оба cached-профиля включаются только явно.

Для Lyra параметр `LEXXOS_RK3506_VM_FAST_LOOP` (ON) включает
программный быстрый цикл: счётчик инструкций локален, проверка
отмены и лимита пакетная (до 256 инструкций), а регистр x0
читается как ноль без DDR и никогда не записывается. При OFF
используется прежний цикл для A/B. Добавлен сценарий `zero`
для регрессионной проверки x0. В тесте `host-reg` число
итераций увеличено в 64 раза для таймера с разрешением 1 мс.

Для RK3506 параметр `LEXXOS_RK3506_VM_ALIGNED_ACCESS` (по умолчанию ON)
разрешает компилятору использовать выровненные 16/32-битные
операции загрузки и сохранения. При OFF остаётся побайтовый путь.
Проверки адресов и выравнивания сохраняются в обоих режимах.
Отчёт содержит `rv32i/aligned-access`.

Профиль `vm-detail` поддерживает `--vm-case substring` для запуска
только совпадающих по имени сценариев (например, `op.`, `imm.`,
`load.`, `store.`, `beq`, `jump.`, `mix.`). Если совпадений нет,
отчёт возвращает ошибку. `--vm-repeat 1..9` выполняет указанный
сценарий несколько раз (по умолчанию 1) и выводит минимум, медиану
и максимум длительности в миллисекундах. `inst-rate` и `loop-rate`
вычисляются по медиане, а каждый повтор независимо проверяет
статус VM, код завершения и число инструкций. Дополнительный буфер
в `VmBenchmarkWorkspace` не выделяется.

| Опция                               | Назначение                                                               |
|-------------------------------------|--------------------------------------------------------------------------|
| `--profile quick/full/soak/sync/vm` | По умолчанию quick                                                       |
| `--duration 1..86400`               | Секунды soak, по умолчанию 300                                           |
| `--iterations 1000..50000000`       | CPU workload; quick 20000, vm 2000, остальные 200000                     |
| `--vm-case substring`               | vm-detail: фильтр по имени сценария (подстрока)                          |
| `--vm-repeat 1..9`                  | vm-detail: число прогонов, по умолчанию 1                                || `--tasks 1..4`                      | Запрошенные worker tasks, по умолчанию 2                                 |
| `--device sd1`                      | Проверяемое блочное устройство; без опции — устройство mount /mnt/sd     |
| `--sd-start lba`                    | Начальный сектор, по умолчанию 0                                         |
| `--sd-blocks 1..1024`               | quick 16, остальные 128; тот же диапазон повторяется в soak              |
| `--write-dir /mnt/sd/NEW-directory` | Явное включение записи, readback и проверки нового тестового файла       |
| `--file-bytes 1..16777216`          | Размер тестового файла, по умолчанию 1048576                             |
| `--io-path /tmp/bench-io.tmp`       | VFS-тест; существующий файл не перезаписывается                          |
| `--out /mnt/sd/report.txt`          | Новый файл отчёта; существующий не перезаписывается                      |
| `--no-save`                         | Только консоль                                                           |
| `--no-display`                      | Пропустить тесты LCD/console renderer                                    |
| `--no-mirror`                       | На время команды остановить текстовый LCD mirror; требует `--no-display` |

Raw SD тест только читает и сравнивает одиночные/пакетные чтения.
Файловый тест проверяет двоичный шаблон; успешно проверенные собственные данные
удаляются, при ошибке сохраняются для разбора. Он требует writable mount именно
выбранного устройства. В текущем FreeRTOS-профиле SD принудительно read-only;
RW тест там недоступен.

## Тест производительности VM RV32I

Профиль `vm` выполняет четыре синтетических программы непосредственно
в production RV32I interpreter:

- `alu` — целочисленная арифметика ADDI/XORI;
- `branch` — условные переходы, включая заведомо взятый переход;
- `memory` — LW/SW в выделенной guest-памяти;
- `ecall` — системный вызов argc без вывода в консоль.

Каждый сценарий содержит цикл заданной длины и заканчивается syscall exit.
Результат проверяется по exit code и точному числу инструкций.

В TSV добавляется секция `rv32i` с полями:
`*-instructions`, `*-elapsed`, `*-rate`, `*-ns-per-inst`.
Время измеряется по системному uptime с разрешением 1 мс;
при коротких измерениях нужно увеличить `--iterations`.

Профиль не читает .lexx с SD, не выполняет файловые операции
и не выводит текст в измеряемом цикле. Он использует рабочую
область в ProgramMemoryArena и ту же VM, что и lexx-run.

Профиль предназначен для оценки interpreter throughput.
Он не измеряет загрузку приложения, рендеринг, VFS и
задержку пользовательского ввода. Для оценки реальной реакции
приложений понадобятся отдельные замеры syscall и UI latency.

Без `--out` создаётся timestamped файл в `/mnt/sd`. Если хранилище недоступно,
тест продолжает работать с `output save skipped`; отсутствие автоматического
сохранения не считается ошибкой измерений. Отказ явно указанного `--out` считается
ошибкой. `/tmp` слишком мал для полного отчёта; сохраняйте UART-лог на компьютере.

## Что содержит отчёт

- Версия/время сборки, board/kernel, доступные частоты.
- CPU, память, scheduler latency; для полного прогона — RTOS и многозадачность.
- Heap, минимум свободного heap с загрузки, резерв arena, стеки и приоритеты задач.
- Состояние I²C/input/display/block devices, cached-счётчики southbridge.
- SD read bytes/rate, min/max/mean задержек запросов, результат сравнения.
- LCD blit/stream и console renderer; для Lyra — cumulative SPI/DMA/SD counters,
  очередь текста, max-parse/max-flush в мс и draw/copy/queue/present ticks кадров.
- Время каждого этапа, начатые раунды, завершённые этапы, ошибки и skipped/n/a.

Отчёт сбрасывается по этапам. `phase elapsed` исключает вывод отчёта, общее время
включает вывод и sync. В summary добавлены `phase-work` (сумма времени фаз),
`report-output` (время write/sync до summary, включая вытеснение задачами) и
`report-rows` (строки до summary). Это время не является чистым UART TX time.
Разрешение таймера — 1 мс; старые синтетические скорости
для нулевого elapsed используют нижнюю границу 1 мс. Watermark стека — минимум
свободного стека задачи за её жизнь, а не текущее потребление. CPU utilization
и электрическая мощность пока `n/a`. Устройства без активного теста перечислены
как inventory; это не успешная проверка их функций.

Код возврата: 0 — завершение без зарегистрированных ошибок; 1 — ошибка теста
или явного вывода; 2 — неверные аргументы; 130 — отмена.
`completed` не означает полной аппаратной приёмки: учитывайте skipped/n/a.

Стек задачи `bench` — 16384 байта. После переполнения 5120-байтного стека на Lyra
это диагностический запас; его достаточность нужно подтвердить watermark на плате.

## Текст на LCD Lyra

Текстовый mirror показывает последние строки актуальной страницы без анимации
прокрутки. Навигация по истории отделена от вывода и выполняется существующими
Alt/Ctrl сочетаниями. История ограничена размером terminal history buffer;
полный TSV-отчёт сохраняйте через UART или файл. `queued-chars` показывает ещё
не разобранный хвост вывода; по завершении он должен уменьшаться до нуля.
