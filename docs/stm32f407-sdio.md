# microSD через SDIO на STM32F407

Документ описывает нативный backend SD-карты для платы Euse M4 DEMO Large.

## Подключение платы

Разъём microSD подключён к периферии SDIO STM32F407:

```text
SDIO_CK   PC12
SDIO_CMD  PD2
SDIO_D0   PC8
SDIO_D3   PC11 / CD-DAT3
```

Линии `DAT1` и `DAT2` в профиле платы не разведены, поэтому драйвер работает в однобитном режиме. `PC11` используется
как `DAT3` и pull-up helper, но не считается надёжным механическим card-detect.

## Реализованные возможности

- настройка GPIO в AF12;
- частота идентификации 400 кГц;
- рабочая частота 24 МГц;
- CMD0, CMD8, CMD55/ACMD41, CMD2, CMD3, CMD9, CMD7 и ACMD6;
- чтение CSD и определение ёмкости SDSC/SDHC/SDXC;
- чтение CMD17 и запись CMD24 одного блока;
- регистрация `sd0` как `BlockDevice`.

Пока не реализованы DMA, полноценные multi-block операции, card-detect interrupt, hot-plug monitoring и четырёхбитный
режим.

## Проверка

После прошивки при установленной карте в boot log не должно быть сообщения `sd card: no-bus`.

```text
board
storage
storage probe
storage read0
storage diag
block-devs
mount
fs-info
ls /mnt/sd
fat-cache
sd-test
```

`sd-test` создаёт `/mnt/sd/LEXTEST.TXT`, записывает данные, выполняет `sync`, читает файл обратно, проверяет содержимое
и
удаляет файл. Это основной быстрый тест после успешного `storage read0`.

При FAT32 автоматическое монтирование может подключить `/dev/sd0` к `/mnt/sd` во время загрузки.

## Ожидаемый вывод board

```text
sd/sdio: clk=44 cmd=50 d0=40 d1=n/a d2=n/a d3=43 init-hz=400000 xfer-hz=24000000
```

Пины кодируются как `port * 16 + pin`, где `A = 0`, `B = 1` и так далее:

```text
PC12 = 44
PD2  = 50
PC8  = 40
PC11 = 43
```

## Диагностика

Если `storage probe` возвращает `timeout`, проверьте установку и исправность карты, питание платы, отсутствие конфликта
на PC12/PD2/PC8 и попробуйте снизить рабочую частоту с `24000000` до `12000000`.

Если `storage read0` работает, а FAT не монтируется, соберите:

```text
storage diag
hexdump /dev/sd0
fs-info
fat-cache
sd-debug
```

Первый backend намеренно использует polling. DMA следует добавлять после подтверждения одиночного чтения и записи на
реальной плате.

## Буферизация консоли

USART1 использует RX ring buffer с обработкой по прерыванию. Это необходимо для надёжной вставки текста и
многобайтовых ANSI-последовательностей. Предыдущий polling-вариант мог терять байты, пока shell task спал или выполнял
команду.
