# Заставка PicoCalc / Lyra в U-Boot

Драйвер и полная сборка Rockchip U-Boot 2017.09 с белой надписью `LEXXOS`
на чёрном фоне экрана 320×320. Сборка выполняется отдельным CMake-таргетом
`uboot-rk3506`, не входит в обычную сборку LexxOS и не записывает устройства.

26 октября 2026 пользователь подтвердил успешную работу на своей PicoCalc / Lyra
после обновления: сборка, загрузка и заставка работают. Проверен сценарий обновления
уже подготовленной SD-карты с сохранением её раннего загрузчика SPL/DDR.
Для пустой карты добавлена [сборка полного SD-образа](../../lyra/README.md)
через `sd-image-rk3506`; холодный запуск новой карты ещё требует проверки.

## Сборка из CLion

1. Запустите Docker Desktop (первый запуск требует сети для зависимостей).
2. Выполните Reload CMake Project.
3. Выберите профиль `picocalc-lyra-release` и таргет **uboot-rk3506**, затем Build.
   Также добавлена Run-конфигурация **LexxOS Lyra U-Boot**, привязанная к этому профилю.

Эквивалент из корня проекта:

```sh
cmake --preset picocalc-lyra-release
cmake --build build/picocalc-lyra-release --target uboot-rk3506
```

Результат: `build/picocalc-lyra-release/uboot/uboot.img`, 4194304 байта.
Рядом сохраняются ELF `u-boot`, `u-boot.dtb`, `.config`, `u-boot.its` и `build.json`
с версиями зависимостей и SHA-256 образа. Для другого CMake-профиля результат
находится в его каталоге сборки, в подкаталоге `uboot`.

Python-скрипт сам скачивает исходники и бинарный OP-TEE, проверяет ревизии/хеши,
применяет драйвер, собирает ARM-код в Linux-контейнере и запускает vendor FIT
generator/mkimage. Образ содержит две одинаковые копии FIT в слотах по 2 МиБ,
как задаёт Rockchip SPL config. SPL/DDR loader этот таргет не собирает и не меняет.
Встроенный UART настроен на 1500000 бод.

Повторный вызов проверяет содержимое входных файлов и SHA-256 результата.
Без изменений Docker и загрузка из сети не запускаются. При изменении драйвера,
патча, настроек зависимостей или скриптов образ пересобирается. Временные исходники
принадлежат скрипту; пользовательские checkout он не сбрасывает. Ошибка сборки
прерывает зависимый таргет прошивки и не публикует частичный образ. Кеш можно удалить
вместе с каталогом сборки — следующий запуск скачает зависимости заново.

## Прошивка через update-rk3506

Установите `LEXXOS_RK3506_FLASH_BUILT_UBOOT=ON` в настройках пресета CLion
или передайте эту опцию при конфигурации.

```sh
cmake --preset picocalc-lyra-release -DLEXXOS_RK3506_FLASH_BUILT_UBOOT=ON
```

В Run → Edit Configurations → `update-rk3506` выберите **тот же профиль**
`picocalc-lyra-release`. Затем Run или:

```sh
cmake --build build/picocalc-lyra-release --target update-rk3506
```

Таргет сам проверяет/собирает U-Boot и LexxOS перед интерактивным выбором SD.
Вручную указывать `LEXXOS_RK3506_UBOOT_IMAGE` в этом режиме не нужно, он должен быть
пустым. Для собственного готового образа выключите `FLASH_BUILT_UBOOT` и задайте
реальный путь через `LEXXOS_RK3506_UBOOT_IMAGE`; оба режима одновременно запрещены.
Если оба параметра выключены/пусты, обновляется только `boot`; установленный на карте
U-Boot и его заставка остаются прежними.

Скрипт проверяет removable SD и точную GPT-разметку Lyra. После подтверждения
`FLASH diskNs2 + UBOOT` сравнивает фактические 4 МиБ раздела `uboot` с новым образом.
При совпадении запись U-Boot пропускается. При различии сохраняет полный backup
в `work/backups/rk3506`, записывает только `s1` и проверяет чтение обратно. Далее обновляет
`boot` (`s2`) по прежней процедуре. При ошибке U-Boot до записи `boot` дело не доходит.
SPL, GPT и rootfs не записываются. Обновление двух разделов не атомарно; резервные
копии сохраняются. Дата файла не влияет на сравнение, каждая карта проверяется отдельно.

## Зависимости и совместимость

Полный Luckfox SDK не требуется. Закреплены следующие источники:

- [Rockchip U-Boot](https://github.com/rockchip-linux/u-boot/tree/1c535d65b8509f388d09e49fb6961f49fda35a1d),
  ревизия `1c535d65b8509f388d09e49fb6961f49fda35a1d`.
- [PicoCalc defconfig](https://github.com/nekocharm/picocalc-luckfox-lyra/tree/1edbd23240c8adc5b9dccd6eae6f735515fe75fd),
  `picocalc_rk3506_luckfox_defconfig`.
- [Device tree Lyra](https://github.com/Calculinux/picocalc-drivers/tree/c86eb883f04260348da0b99d19a8ac111493d084),
  `uboot-rk3506-luckfox.dts/.dtsi`.
- [Rockchip rkbin](https://github.com/rockchip-linux/rkbin/tree/3e288fe814e059dd06833495f845cab04ac20a5c),
  `rk3506_tee_v2.50.bin`, адрес загрузки `0x1000` из `RK3506TOS.ini`.

Точные URL и SHA-256 файлов находятся в `sources.json`. В Git проекта нет
скачанных бинарников. Зависимости сохраняют лицензии исходных проектов; OP-TEE
из rkbin распространяется на условиях поставщика, не лицензии LexxOS.

Это сборка для Lyra из закреплённых опубликованных компонентов. Пользователь
подтвердил её работу с SPL/DDR на своей карте. Это подтверждение не распространяется
на другие варианты платы или раннего загрузчика. [Порт полного SD-образа](../../lyra/README.md) сохраняет DTB и блок
`resource`
как отдельные закреплённые компоненты; целый заводской `boot.img` теперь
нужен только при явном выборе старого FIT_TEMPLATE.

## Работа дисплея

GPIO0_A2/A3/A4 — RESET/DC/CS, RM_IO6/7 — SPI0 MOSI/CLK. SPI0 работает на 12 МГц
от OSC24M без DMA. Инициализация соответствует backend ILI9488 LexxOS: RGB666,
MADCTL `0x48`, инверсия включена. Кадр передаётся построчно, display-on выполняется
после заполнения RAM панели. Логотип задаётся массивом `logo` в `picocalc_splash.c`.

Автовывод включён через `CONFIG_PICOCALC_LYRA_SPLASH=y`: в `board_late_init()` перед
`scan_run_cmd()` и обычным autoboot. Quiescent boot его пропускает. Ранние recovery,
USB/charge-пути, покидающие эту функцию раньше, не покрыты. В CLI U-Boot доступна
команда `picocalc_splash`. При ошибке SPI вывод прерывается, загрузка продолжается.
SPI1 и UART0/SWD GPIO0_C6/C7 не перенастраиваются драйвером заставки.

В BootROM/SPL изображения ещё нет. Подсветка зависит от состояния southbridge
PicoCalc; регулирование яркости порт не реализует. LexxOS затем снова инициализирует
панель и очищает её — бесшовное сохранение заставки пока не реализовано.

## Проверки

```sh
sh ports/uboot/picocalc_lyra/tests/run.sh
python3 tools/test_rk3506_uboot_build.py
python3 tools/test_flash_rk3506_macos.py
```

Host-тесты проверяют SPI/MMIO, отказ при таймаутах, упаковку двух слотов, кеш сборки,
vendor `os = "U-Boot"`, условную запись, смену карты и ошибку readback. Они не пишут
в устройства. Реальная полная ARM-сборка проверена через CMake на Mac/Docker;
SHA-256 payload U-Boot, OP-TEE и DTB проверены по метаданным FIT.

Для ручной работы с исходниками остаются `tools/rk3506_fetch_uboot.py` и
`install.py`: они подготавливают отдельный checkout. Новый CMake-таргет использует
свой кеш и не зависит от наличия этого checkout.
