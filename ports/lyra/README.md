# Полный SD-образ PicoCalc / Luckfox Lyra

Порт собирает всю SD-карту как обычный файл: **BootROM → DDR/SPL →
OP-TEE / U-Boot с заставкой → FIT LexxOS → ARMv7-A startup → Runtime / shell**.
BootROM находится в SoC, STM32 southbridge — на отдельном контроллере;
их прошивки эта сборка не меняет. Linux не запускается.

## Сборка

Таргеты разделены по назначению:

| Таргет                     | Действие                                                                                   |
|----------------------------|--------------------------------------------------------------------------------------------|
| `sd-image-rk3506`          | Только собрать файл полного SD-образа                                                      |
| `flash-rk3506`             | Собрать и записать **всю карту**, включая GPT и DDR/SPL                                    |
| `update-rk3506`            | Прежний `flash-rk3506`: обновить boot и при необходимости U-Boot, сохранив остальную карту |
| `list-rk3506-disks`        | Показать съёмные карты, включая пустые                                                     |
| `list-rk3506-update-disks` | Показать карты с разметкой для обновления разделов                                         |

Для полного образа нужны файлы поставщика из `components.json` с указанными
контрольными суммами. Для полной сборки поместите полученные компоненты в
`third_party/rk3506-luckfox-lurra`. Релизный ZIP содержит ядро и инструменты
обновления существующей карты по собственному шаблону FIT. Сборка полного образа из корня проекта
требует ARM toolchain и Docker для U-Boot:

```sh
cmake --preset picocalc-lyra-release
cmake --build build/picocalc-lyra-release --target sd-image-rk3506
```

В другом RK3506-профиле таргет называется так же, результат находится в его
каталоге сборки.
В CLion добавлена конфигурация **LexxOS Lyra SD Image**.

Результат: `lexxos-sd.img` (по умолчанию 128 МиБ), `lexxos-sd.json` с хешами
и происхождением компонентов, `lexxos-sd.img.sha256`. Сборка не обращается к устройствам.
`lexxos_fit` теперь может создавать обычный `lexxos.img` без FIT_TEMPLATE;
явно заданный старый шаблон продолжает работать для существующего обновлятора.
Полный SD-образ всегда использует закреплённый набор `components.json`.

Для карты другого размера **до полной записи** создайте образ точно её размера
в байтах: резервная GPT должна находиться в последнем секторе носителя.
У прочитанной 26 октября 2026 карты размер 4027580416 байт. Проверяйте размер
актуальной карты через `diskutil info /dev/diskN`, номер устройства может измениться.

```sh
cmake --preset picocalc-lyra-release \
  -DLEXXOS_LYRA_SD_SIZE_BYTES=4027580416
cmake --build build/picocalc-lyra-release --target sd-image-rk3506
```

Файл создаётся разреженным: пустые области не занимают полный размер на диске
с поддержкой sparse files. Хеширование всё равно читает весь логический размер.
Компактный образ нельзя просто считать образом с GPT на конце произвольной
большей карты. Для такого носителя пересоберите с точным размером.

Для сохранения заводского Linux rootfs без изменения содержимого:

```sh
cmake --preset picocalc-lyra-release \
  -DLEXXOS_LYRA_SD_SIZE_MIB=320 -DLEXXOS_LYRA_SD_SIZE_BYTES= \
  -DLEXXOS_LYRA_ROOTFS_IMAGE=/path/to/rootfs.img
cmake --build build/picocalc-lyra-release --target sd-image-rk3506
```

Для полной записи примените также точный размер целевой карты. Rootfs не нужен
LexxOS и по умолчанию его раздел пустой, без файловой системы. Опция сохраняет
его для анализа/совместимости, но не добавляет Linux kernel или dual boot.
Снять опции: `-DLEXXOS_LYRA_ROOTFS_IMAGE= -DLEXXOS_LYRA_SD_SIZE_BYTES=`.

## Состав и границы порта

| Компонент    | Реализация сейчас                                                                                                    |
|--------------|----------------------------------------------------------------------------------------------------------------------|
| DDR + SPL    | Неизменный RKNS v2 idblock с рабочей карты; SHA-256 заголовка и обоих payload проверяются                            |
| OP-TEE       | Существующий закреплённый бинарник rkbin в сборке U-Boot                                                             |
| U-Boot       | Переиспользуется [существующий порт](../uboot/picocalc_lyra/README.md), без второго checkout и дублирования драйвера |
| FIT платы    | Сохранённый заголовок, `board.dtb`, `resource.img`; Linux payload отсутствует среди новых компонентов                |
| LexxOS       | Существующие ARMv7-A startup, RK3506 backend и PicoCalc board profile; код ядра не копируется                        |
| STM32        | Существующая прошивка контроллера; никакой записи контроллера из этого порта                                         |
| GPT / SD     | `build.py`, границы совместимы с текущим `update-rk3506`                                                             |
| Linux rootfs | Необязательный неизменный входной файл                                                                               |

Контрольные суммы и происхождение требуемых бинарных компонентов указаны
в `components.json`. Для сборки достаточно отдельных компонентов.
Сторонние компоненты сохраняют лицензии поставщиков; см. README рядом с ними.
Это порт сборки с сохранением бинарников DDR/SPL и DTB, а не заявление
о пересборке всех частей SDK из исходников.

| Область                      |               Начало |                        Размер |
|------------------------------|---------------------:|------------------------------:|
| Protective MBR + primary GPT |                LBA 0 |                    34 сектора |
| DDR/SPL idblock              |               LBA 64 |                   196608 байт |
| U-Boot                       |     LBA 8192 / 4 МиБ | 4 МиБ, два слота FIT по 2 МиБ |
| Boot FIT                     |    LBA 16384 / 8 МиБ |                 Раздел 12 МиБ |
| Rootfs / резерв              |   LBA 65536 / 32 МиБ |              До резервной GPT |
| Backup GPT                   | Последние 33 сектора |                    16896 байт |

GUID типов разделов оставлены как на рабочей карте, чтобы существующий
обновлятор распознавал их. UUID экземпляров генерируются детерминированно;
одинаковые образы имеют одинаковые UUID. Не следует использовать их для
различения нескольких одновременно подключённых клонов.

## Что установлено по дампу

26 октября 2026 прочитан полный дамп 4027580416 байт:
SHA-256 `343729f9412d6e3d2dbf517aea02e92a968f2e2254d51f2b760b5bb0a0cab1ef`.
CRC обеих GPT корректны. U-Boot совпал с текущим собранным образом;
DTB и resource совпали с прежним `third_party/.../boot.img`.
DDR/SPL отличается от SDK 261020, поэтому сохранён вариант с рабочей карты.
Извлечены только 196608 байт, длина определена по двум дескрипторам RKNS v2
из `tools/rkcommon.c` закреплённого SDK U-Boot. SHA-256 обоих payload и заголовка
валидны. Остатки старых файлов вне разделов не перенесены.

В `vendor/mk-sd-updateimg.sh` сохранён без изменений скрипт производителя
из закреплённого `device/rockchip` для документирования SD-смещений.
Наша сборка его не запускает: GPT генерируется Python без sudo, loop devices
и Linux-утилит. Новый `MiniLoaderAll.bin` не подменяет SD idblock.

## Проверки и запись

```sh
python3 -m unittest discover -s ports/lyra/tests -v
python3 ports/lyra/build.py --verify build/picocalc-lyra-release/lexxos-sd.img
```

Проверяются primary/backup GPT и CRC, границы, исходный DDR/SPL, обе копии U-Boot,
SHA-256 FIT payload, неизменность board DTB/resource, адреса загрузки/входа.
При наличии соседнего JSON также проверяется SHA-256 всего файла, включая rootfs.
Сборка публикует файл только после проверки временного образа.

Для первичной установки или полной перезаписи в CLion выполните Reload CMake
Project и выберите `flash-rk3506` либо **LexxOS Lyra Flash SD**:

```sh
cmake --build build/picocalc-lyra-release --target flash-rk3506
```

Этот таргет собирает LexxOS и U-Boot, предлагает выбрать съёмную карту (пустая
карта тоже подходит), затем создаёт образ **точно её размера** в отдельном
каталоге `build/picocalc-lyra-release/flash-*/lexxos-sd.img`.
Размеры `LEXXOS_LYRA_SD_SIZE_BYTES/MIB` здесь не используются: они задают только
размер файла для `sd-image-rk3506`. Образ и manifest сохраняются для анализа.

После проверки образа выводится запрос `ERASE diskN ALL`. После подтверждения:
проверка носителя → размонтирование → полный backup карты в `work/backups/rk3506`
с SHA-256 → запись всего образа → чтение всей карты и сравнение SHA-256 → eject.
Пароль вводится через sudo в терминале. Ctrl+T показывает прогресс dd.
Нужно свободное место для полного backup; при его нехватке запись не начинается.
При ошибке записи/проверки backup сохраняется, успешный eject не выполняется.

Полная запись заменяет все прежние данные, включая rootfs. По умолчанию новый
rootfs-раздел пустой; `LEXXOS_LYRA_ROOTFS_IMAGE` позволяет включить заданный rootfs.
DDR/SPL и ресурсы платы остаются закреплёнными бинарниками из этого порта,
а прошивка STM32 не меняется. `LEXXOS_RK3506_FLASH_BUILT_UBOOT` и
`LEXXOS_RK3506_UBOOT_IMAGE` относятся только к `update-rk3506`; полный flash
всегда включает U-Boot из сборки проекта.

Для обычного быстрого обновления выберите `update-rk3506` / **LexxOS Lyra Update**:

```sh
cmake --build build/picocalc-lyra-release --target update-rk3506
```

Он обновляет `boot`/`uboot` уже размеченной карты и сохраняет GPT, DDR/SPL и rootfs.

Холодный запуск полной новой карты ещё не проверен. Проверить:
DDR/SPL UART → U-Boot и заставка → LexxOS shell, клавиатуру/дисплей, системную
SD только для чтения, съёмную SD PicoCalc, перезапуск и SWD.
Это отдельная проверка от уже подтверждённого обновления U-Boot на старой карте.

## Архитектура из схемы

Схема пользователя задаёт уровни ответственности, а не порядок исполнения:
CPU architecture → SoC/platform → board → устройства, с общим ядром поверх них.
Порт сборки не переносит SoC-регистры в общее ядро и не меняет пины платы.

- CPU: текущий ARMv7-A startup, исключения и переключение контекста.
- SoC: текущие RK3506 IRQ, timer, UART, SPI, SDMMC, I2C и DMA backends.
- Board: текущие параметры PicoCalc Lyra и подключение STM32/дисплея/SD.
- OS Core: существующие Runtime, shell, VFS и приложения.

Физическое выделение смешанных CPU/SoC файлов в новые каталоги — следующий
рефакторинг. Для первого полного SD-образа они намеренно используются как есть.
